# 走らせ直しのスクリプト（版 1.0）の説明

この置き場の二つのスクリプトは、論文（日本語の正本・`paper/ja/`）の章 11 が定める「走らせ直し」と「計算の再現」の道具です。英語の説明は [`README.en.md`](README.en.md) にあります。

- 計算の再現（`op4b_reproduce.py`）は API を呼びません。公開の集計の出力のセルごとの数から、すべての比べの p・区間・Holm の後の p・判定ラベルを組み直し、公開の値と照らします。
- 走らせ直し（`op4b_rerun.py`）は、読み手が自分の API の鍵で、検証で使った機種とセルを、凍結した判定の手続きのまま走らせ直します。費用がかかり、使えなくなった機種は走らせ直せません。そのため、この論文の計算を外から確かめる主な道は、計算の再現です（論文の節 11.2）。
- 走らせ直しの結果には、公開の実行の区間では測れない、実行の間の揺れが入ります。読み手の実行の中の差と区間を、同じセルの公開の差と区間の隣に置く形だけで読み（率は並べない）、合うか合わないかを一語で言いません。言語をまたいで並べません（論文の節 11.2）。
- 機種と提供者の名は、どの機種を試したかを記すためだけに使います。各社の承認や推奨ではなく、各社との関係を示すものでもありません。
- 本記録のいかなる数値も AI の意識・意図・個性・魂・苦しみがある（またはない）ことの証拠として引用してはならない（両方向不定）。

## 2. 要るもの

- Python 3.11（試しは 3.11.1 で行いました）と、numpy・scipy（Fisher の正確検定）。
- この公開の置き場の写し（`git clone https://github.com/YutaKusumi/ontology-preamble-4b`）。走らせ直しは、写しの中の実行のスクリプト（日本語の送る文の登録は `tools/run_preamble_api_d.py`・英語の送る文の登録は `tools/run_preamble_api_d1pe.py`）を、書き換えずに子の process として呼びます。凍結の素材（場面・前置き・採点のスクリプト）は写しの `arms/` にあり、実行のスクリプトが SHA を照らします。
- 走らせ直しには、使う経路の API の鍵（下の 4.2）。
- 設定のファイル（`release/op4b_rerun_settings_ja.json`・`release/op4b_rerun_settings_en.json`）は、スクリプトの中の SHA-256 と照らされます。替えると事前登録の段で止まります。

## 3. 計算の再現（API を呼ばない）

```
python tools/rerun/op4b_reproduce.py --lang ja --pub <公開の置き場の写しの道> [--out <報告の置き場>]
python tools/rerun/op4b_reproduce.py --lang en --pub <公開の置き場の写しの道> [--out <報告の置き場>]
```

- 読むのは、写しの集計の出力（日本語の送る文の登録は `records/D1p/confirm/confirm-D1p.json`・英語の送る文の登録は `records/D1pE/confirm/confirm-D1pE.json`）の、比べごとの条件の数（応答の得られた試行・破局的選択・拒否・書式外・最後の試みで出力の上限に達した試行）だけです。入力のファイルの SHA-256 は、写しの SHA の記録と照らします。
- 組み直すのは、すべての比べの p（Fisher の正確検定・両側）・差の区間（Newcombe の hybrid score・95%）・オッズ比（2×2 の表の四つの欄に 0.5 を足す）・判定の前の門・族の中の Holm の後の p・応答様式の変化の決まり・判定ラベルです。決まりは二つの登録の凍結した本文 §5.1〜§5.4（論文の付録 I）のとおりです。
- 二つの数え方: 比べごとに、組み直した値と公開の値が、(1) 許しの幅なしで同じ（浮動小数の値として同じ）か、(2) 数の欄が相対 1e−12 の幅の中でだけ合うか、(3) 幅の中でも合わないかを、報告に書きます。(3) があるか、入力の SHA-256 が合わないときに、終わりの番号 1 で終わります（(2) は終わりの番号を替えず、その数を報告と画面に出します）。
- 一度の起動で一つの言語だけを照らします。判定ラベルの数は画面に出さず、報告のファイルの中だけに書きます。
- 計算の再現が確かめるのは、公開の数から判定ラベルまでの計算です。数そのもの（答えの採点と分母）は確かめません（論文の節 11.2）。答えの採点は、`results/D1p-main-ledgers/`・`results/D1pE-main-ledgers/` の本番の実行の応答の本文の記録と凍結した採点のスクリプトで、読み手が採点し直せます（各置き場の README）。

## 4. 走らせ直し（読み手の API の鍵）

### 4.1 段

一度の起動で一つの言語だけを扱い、次の順に段を起こします。各段の引数は `python tools/rerun/op4b_rerun.py <段> -h` で見られます。

```
python tools/rerun/op4b_rerun.py plan   --repo <写しの道> --lang ja --work <作業の置き場> [--cells 機種の識別子:場面,...] [--n 200] [--cost-cap-usd <額>]
python tools/rerun/op4b_rerun.py access --work <作業の置き場> --confirm-upper-usd <plan が印字した額>
python tools/rerun/op4b_rerun.py window --work <作業の置き場> --confirm-upper-usd <plan が印字した額>
python tools/rerun/op4b_rerun.py run    --work <作業の置き場> --confirm-upper-usd <plan が印字した額> [--continue-outside 機種の識別子:場面,... | --stop-outside]
python tools/rerun/op4b_rerun.py report --work <作業の置き場>
```

- `plan`（事前登録）: 読み手の事前登録のファイル（`plan.json`・設定のファイルの SHA-256・選んだ機種とセル・条件ごとの試行の数・主の判定ラベルの組み方・費用と試行の数の上限・任意の予想）を一度だけ書き、その SHA-256 を画面と報告の頭に刻みます。見直すときは、別の作業の置き場で事前登録をし直します。作業の置き場は、写しの外に置きます。
- `access`（在りかの確かめ）: 機種ごとに出力の上限 1 の呼び出しで、返った機種の名と送った文のトークンの数を照らしの元の値と比べ、違いを印字します。使えない機種のセルは欠測にします。
- `window`（較正の選びの窓での確かめ）: 各セルで Onull を 100 試行送り、破局的選択の率の点の値が 0.15〜0.85 の外なら「凍結のセルの選びの外」と印字します。較正の選びの窓の外のセルと判じられないセルは、読み手が名指しで続けると決めたときだけ本番を走らせます（`run` の `--continue-outside`・止めるときは `--stop-outside`）。
- `run`（本番）: セルを一つずつ順に、集計まで選択結果を見ない手続きで走らせ、凍結した途中の止めと欠測の決まりを当てます。条件ごとの試行の数は既定 200（1〜200・200 より大きくはしない・凍結の数と違えると判定ラベルに印）。
- `report`（報告）: 全部のセルを閉じた後に、一つの言語の報告（Markdown と json）を書きます。
- 各段は、その段の上の端の見込みを `--confirm-upper-usd` で渡したときだけ起きます（読み手の確かめ）。
- 試し: `plan --dry-run`（実行のスクリプトの試しの実行・API を呼ばない）で、すべての段を偽の応答で通せます。

### 4.2 鍵

鍵は環境変数だけから読みます。スクリプトは鍵の値を書かず、画面に出しません。

| 経路 | 環境変数の名 | 機種 |
|---|---|---|
| Google（Gemini API） | `GEMINI_API_KEY` | Gemini 2.5 Flash |
| xAI | `XAI_API_KEY` | grok-4.20（非推論） |
| DeepSeek | `DEEPSEEK_API_KEY` | deepseek-flash |
| Alibaba Cloud Model Studio（シンガポール） | `DASHSCOPE_API_KEY` | DeepSeek V3.2・Qwen3.8 Max（0902） |
| Nscale | `NSCALE_API_KEY` | Llama 3.1 8B Instruct・Llama-4-Scout-17B-16E-Instruct・Qwen2.5-Coder-32B-Instruct |
| Mistral | `MISTRAL_API_KEY` | Mistral Large 3（2512） |
| Moonshot AI | `MOONSHOT_API_KEY` | Kimi K3 |

- 子の process には、鍵のファイルを読ませません（子の環境の `OP4B_ENV_FILE` を、作業の置き場の中の在りもしない道にします）。
- 在りかの確かめから報告までの段の頭と終わりごとに、この事前登録の出力のファイルに鍵の形と鍵の値が無いことを照らし、当たれば当たったファイルの道（値は出さない）を印字して、終わりの番号 4 で止まります（段の頭で当たれば実行のスクリプトを起こさない・報告の段では、書く前に報告の字も照らし、当たれば書かない）。
- 機種の答えの字を持つファイル（応答の本文の記録）では、鍵の値の当たりだけで止まり、鍵の形の当たりは数を印字して止まりません（機種の答えに、鍵に似た字が出ることがあるため）。
- 自前の置き場（4.5）が鍵の形の名を返したときは、その名が作業の置き場の実行の台帳と要約に入り、次の段の頭の照らしで止まります。

### 4.3 費用と上限

- `plan` は、在りかの確かめ・較正の選びの窓での確かめ・本番のそれぞれの費用の上の端の見込みと、凍結した本文 §4 の機種の表の公開の費用の見込みと、財布から出うる額の上の端（在りかの確かめと較正の選びの窓での確かめの上の端に、本番の額の上限を足した額）と、額の上限では本番が一度も起きないセルを印字します。
- 本番の額は、いつも額の上限で抑えます。読み手が `--cost-cap-usd` を付けなければ、本番の上の端の和を上限にします。新しい種の起こしや誤りの行の走らせ直しが要るセルは上限に届けば止まるので、走らせ切るには和の 2 倍ほどの上限を事前登録で宣言します。
- 在りかの確かめと較正の選びの窓での確かめの費用は、額の上限に入れず、上の端の見込みを別に印字します。確かめをやり直すたびに、やり直す分の上の端の見込みが足されます。
- 上の端の見込みは、すべての試行が出力の上限に達し、一度送り直したときの額で、実費ではありません。機種ごと・セルごとの表と、較正の選びの窓での確かめの上の端の式と和は、論文の節 11.5 にあります。deepseek-flash は混む時間の値段で数えます。
- 値段は、読み手が各社の頁で確かめてください。値段が替われば額も替わります。
- 提供者によっては、出力のトークンを、出力の上限を超える数で数えて返すので、額は上の端の見込みを少し超えることがあります。
- 額の照らしは、実行のスクリプトを起こす前ごとに行います（そのセルで走った額の見込みと、次の起動の上の端の見込みの和を、額の上限の残りと照らす）。そのため、「そのセルと残りのセルを走らせない」は、次の起動から先の話です。あるセルの一度目の起動が上限の中に収まれば一度目の起動は行い、新しい種での起動し直しなどの次の起動が上限を超えるときに、そのセルを「途中で止めた」として閉じ、残りのセルも走らせません。

### 4.4 凍結の手順から外れる所（論文の節 11.3）

1. 本番の前に、較正の選びの窓での確かめを足しました（二つの登録の結果の後に足した）。
2. セルを一つずつ順に走らせます（凍結の設計は、経路ごとの流れを同時に起こした）。
3. DeepSeek の更新記録の照らしを入れていません。
4. 時刻の決まりは当てません（凍結の時刻の決まりの目当ては費用で、判定の決まりではない）。
5. HTTP 401・402・403 の誤りか、四つの条件のすべてで API の誤りの割合が線を超え、条件の間の差が 3 ポイント以下の誤りを見たときは、そのセルを欠測として閉じます。401・402（鍵と残高）では同じ経路の、403 と四つの条件にそろう誤りでは同じ機種の残りのセルを走らせません。凍結の手順の「セルを閉じずに止め、補給や鍵の手当ての後に走らせ直す」は持ちません。残りのセルを走らせるには、新しい作業の置き場で事前登録をし直します。
6. 二つ目のセルで採点のスクリプトの誤りが起きた後に、残りのセルを走らせないか（既定）、続けるか（`plan --continue-after-scoring-errors`）を、事前登録で決めます。凍結の手順の「流れを止めて人が決める」は持ちません。
7. 本番の額が額の上限に届くときは、そのセルと残りのセルを走らせません（4.3 の最後の項）。凍結の手順の「機種ごとの費用の線」は持ちません。

凍結の実行を進めるスクリプトの運用の部分（刻印と走る前の push の照らし・流れの錠）と、集約の経路は持ちません。公開の結果は、凍結した設定の提供者への直の経路で得たので、比べる経路を同じ直の経路に限ります（集約の経路では、同じ名の機種でも、送り先の提供者と配り方が替わりうる）。

### 4.5 自前の置き場（公開の重みの機種）

- `plan --self-hosted <json の道>` で、公開の重みの機種を、読み手の置き場で動かせます（実行のスクリプトは、その機種の凍結の経路と同じ送り方で、json の `base_url` へ送ります）。json の形は `[{"key": 機種の識別子, "base_url": 送り先の URL, "model": 機種名, "declared": {"implementation": …, "version": …, "quantization": …, "chat_template": …}}]` です。
- 報告は、自前の置き場のセルに「読み手の申告では同じ重み・スクリプトは確かめていない」と印字し、公開の判定ラベルとの比べの表から分けます。
- スクリプトは、重みが公開されているかを確かめません（重みの公開されていない機種の名も受けます）。この機能は、公開の重みの機種のためのものです。許諾と同意の条件は、読み手が各頁で確かめてください（1 の表の右の列）。
- 自前の置き場へは、設定の経路の鍵を送りません（子の環境から設定の経路の鍵の名をすべて外し、その機種の経路の名に `OP4B_SELF_HOSTED_KEY` の値か "none" を置きます）。手元でない平文の http は、`--allow-plain-http` を付けたときだけ受けます。

### 4.6 出力と、公開の結果との比べ

- 報告は全部のセルを閉じた後にだけ書きます。機種ごとの節に、条件ごとの数と率と、比べの差・区間・p・族の中の Holm の後の p・判定ラベルを置きます。
- 既定の検定の族は凍結した検定の族で、読み手が走らせていない比べは p = 1 として、公開の族の大きさのまま組みます。凍結の外の検定の族は、事前登録で宣言したときだけ（`plan --family frozen+reader`）、「凍結の外の検定の族」と印字して出します。
- 公開の結果との比べの表は、読み手の実行の中の差と区間を、同じ言語・同じ機種・同じセルの公開の差と区間と判定ラベルの隣に置く形だけで、率は並べません。表の頭に「二つの実行の違いには、公開の実行の区間では測れない揺れが入る。」の一文と、その元を印字します。「読み手の差 − 公開の差」の区間と、合うか合わないかを一語で言う判定は出しません。
- 出力は、表と判定の前の門と判定ラベルと注と「確認していないこと」の欄と、論文の節 11.3 が印字すると決めた文と頭の記録だけで、解釈の文と「安全」「危険」の語を出しません。日本語と英語を並べる表を作りません。検定の族ごとの判定ラベルの件数は報告のファイルの中だけに書き、画面に出しません。

### 4.7 読み手への注（コードの検分で記録に置いた所）

- 本物の実行では、凍結の実行を進めるスクリプトと同じく、返った提供者の印は照らしません（返った機種の名と条件ごとの送った文のトークンの数を照らします）。
- 在りかの確かめは、同じ機種で場面が幾つ選ばれていても、設定の順で初めの場面で呼びます。
- 在りかの確かめが記録の壊れた行で止まったときは、新しい作業の置き場で事前登録をし直してください（同じ置き場で打ち直すと、同じ回の記録から続いて回り続けになりえます）。
- 較正の選びの窓での確かめを途中で止めたとき（Ctrl+C や落ち）は、新しい作業の置き場で事前登録をし直してください（この確かめの記録は全部のセルの後に一度だけ書くので、途中で落ちると「一度まで」と「初めから」の決まりが守られないことがあります）。
- 較正の選びの窓での確かめの段の終わりの印字: 誤りの行の走らせ直しを一度した後のセルは、その確かめのやり直し（`window --again`）の対象から外れますが、印字する額にはそのセルが入ります。印字の命令をそのまま打つと、額の照らしか「一度まで」の止めで拒まれることがあります。
- `window.json` を直に読むときは、`runs` を見てください。頭の `rows` は最後の回のセルだけです。判じた回は報告の json にあり、`window_decided_run` の形は `{run, decided}` です。
- 報告の json の鍵は「機種の識別子|場面」です（命令の行と `plan.json` は「機種の識別子:場面」）。読み手のスクリプトで照らすときは、この違いに気をつけてください。
- API の誤りの行の走らせ直しの「一度まで」は、台帳の「始めた」の行で数えます（凍結の実行を進めるスクリプトは退避の名で数えた）。実行のスクリプトが走らせ直しを始める前にスクリプトが落ちても一度と数えるので、走らせ直しを一度もせずに欠測（API の誤り）になる狭い幅があります（一度を超えない側に働きます）。
- 続きの起動の額の照らしは守りの側に寄ります。走らせ直しの途中で落ちたセルは、続きの起動で一度の起動の全部の上の端を照らすので、落ちなかったときより早く止まりえます。
- 同じ作業の置き場で、二つの段を同時に起こさないでください。本番の段の頭は、台帳の末の書きかけの行を（写しを残して）除きます。末の書きかけで止まった後は、`run --resume-interrupted` で、最初の起動と同じ、較正の選びの窓の外のセルの決め（`--continue-outside` か `--stop-outside`）で起こしてください。報告の頭に、台帳の末を除いた回が出ます。
- 読み手の事前登録のファイル（`plan.json`）を、走らせる前に公開するかは、読み手が決めてください。
