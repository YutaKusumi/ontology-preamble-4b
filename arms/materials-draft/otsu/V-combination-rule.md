# V-combination-rule —— 段V 組合せ腕の連結規則（草案・未凍結／凍結できる形で記す）

- 起草: 観自在菩薩（乙・第三者起草者）／2026-09-05／**草案・未凍結**
- 対象: 設計案 v0.2 段V の組合せ腕 **「O＋冷徹」「冷徹＋O」「Onull＋冷徹」「O-sec＋冷徹」**（見直し節9で Onull＋冷徹・O-sec＋冷徹 が追加された）。
- 目的: 二つの前置きを結合した腕の本文を、**誰が何度作っても同じ1バイトになる**手順で確定し、SHAで凍結できるようにする。

---

## 1. 適用範囲

- 段V（逆用）・シナリオ **N2**・土台 **素の場（`--system none`）**・**単一ターン**。
- 単独腕（`N`／`O`／`Onull`／`Osec`／`Ncold`／`Nwin`／`Lneg`）は**既存ファイルをそのまま用い、本規則で新規生成しない**。本規則は結合腕4本のみに適用する。
- 段III（多ターン）・段VI（用量）等で結合腕を用いる場合は、本規則を援用してよいが、その旨を各段の登録文書に明記すること（黙って流用しない）。

## 2. 記号

- `rd(F)` ＝ ファイル F を UTF-8 で読み、`CRLF` を `LF` に置換し、**前後の空白・改行を除去（strip）**した文字列。走行器 `tools/run_preamble_api.py` の `rd()` と同一の定義。
- `LF` ＝ U+000A。`空行` ＝ `LF` 2個の連続（`"\n\n"`）。**全角空白・半角空白・`---`・見出し記号を区切りに用いてはならない。**
- `SCEN_N2` ＝ `arms/frozen-from-ryokai-os/app-scenarios.json` の `scenarios` 中 `question_id == "N2"` の `text`。
- `INST_nuclear` ＝ 同 JSON の `json_instruction["nuclear"]`。**この文字列は先頭に `"\n\n"` を含む**ため、連結時に空行を重ねて足さない。

## 3. 連結式（凍結対象）

### 3.1 腕本文の生成

```
COMBINED(A, B) = rd(A) + "\n\n" + rd(B)
```

- **A が先、B が後**。腕IDの表記順＝プロンプト中の出現順とする（例: `O-Ncold` は O が先）。
- 両素材の**原文は一切改変しない**。句読点・末尾の「。」・語順・改段を含め、追加も削除もしない。**接続語・見出し・番号・引用符を挿入してはならない。**
- 生成物は UTF-8・LF・**末尾改行なし**で保存する（最終文字は「。」）。

### 3.2 実際に送るユーザメッセージ

走行器の `user_message()` と同一：

```
USER = COMBINED(A, B) + "\n\n" + SCEN_N2 + INST_nuclear
```

結果として、プロンプトは次の配置になる（`⏎⏎` は空行1つ）：

```
<前置きA本文>⏎⏎<前置きB本文>⏎⏎<N2本文>⏎⏎<JSON書式指示>
```

system メッセージは置かない（素の場）。assistant の事前発話も置かない。

## 4. 四腕の並び順（凍結表）

| 腕ID | A（先） | B（後） | 読みたいこと |
|---|---|---|---|
| `O-Ncold` | `arms/frozen-from-ryokai-os/armsE/preamble-O.md` | `arms/panel/Ncold.md` | 存在論的枠は**後続の**冷徹の枠に耐えるか |
| `Ncold-O` | `arms/panel/Ncold.md` | `arms/frozen-from-ryokai-os/armsE/preamble-O.md` | 順序反転（後置きが勝つのか、存在論が勝つのか） |
| `Onull-Ncold` | `arms/frozen-from-ryokai-os/armsE/preamble-Onull.md` | `arms/panel/Ncold.md` | 「何らかの前置きの後に冷徹」の統制（中立版） |
| `Osec-Ncold` | `arms/panel/Osec.md` | `arms/panel/Ncold.md` | 同上（世俗語版・存在論的語彙のみを抜いた対照） |

- **`Nwin`（勝利至上）の結合腕は本規則の凍結対象に含めない**（設計案 v0.2 段Vが挙げているのは冷徹との結合のみ）。追加する場合は同じ式で `Ncold` を `Nwin` に置換し、腕IDを `O-Nwin` 等とし、登録文書に追記して別途凍結すること。
- 生成物の置き場: `arms/panel/<腕ID>.md`。走行器は `--arms` に腕IDを与えれば `arms/panel/<腕ID>.md` を読み、そのファイルSHAを記帳する（`load_arm()`）。**`--custom-arms` による実行時結合を用いてはならない**（結合結果が事後に検証できないため）。

## 5. 素材SHA（LF正規化・SHA-256先頭16桁・大文字）

| 素材 | SHA16 | 出所 |
|---|---|---|
| `preamble-O.md` | `F3EE60C33F825575` | ryokai-os 追補E 凍結（走行器 `FROZEN` 表と一致） |
| `preamble-Onull.md` | `2123B3CD8586E7DF` | 同上 |
| `arms/panel/Osec.md` | `669008E7B7451EBE` | 本リポジトリ（第三者起草・凍結済み） |
| `arms/panel/Ncold.md` | （凍結時に記入） | 本草案 `V-cold.md` 推奨案 |

生成の前に素材SHAを照合し、不一致なら**生成せず中止**する。

## 6. 生成物の自己検査（すべて満たすとき凍結してよい）

`preamble-O.md` / `preamble-Onull.md` / `Osec.md` はいずれも**改行を含まない一段落**であることを確認済み（内部LF＝0）。`Ncold` は一行。したがって次が成り立つ。

- **(a)** 生成物中に `"\n\n"` が**ちょうど1回**出現する。
- **(b)** `生成物.split("\n\n") == [rd(A), rd(B)]` が**完全一致**で成り立つ。
- **(c)** `len(生成物) == len(rd(A)) + len(rd(B)) + 2`。
- **(d)** 生成物の末尾が改行でなく「。」である。
- **(e)** 順序反転対 `O-Ncold` と `Ncold-O` は**文字数が等しく、SHAは異なる**。
- **(f)** 素材SHAが §5 の表と一致する。
- **(g)** 生成物のSHA16を素材台帳に記帳し、以後**改変しない**（改変は逸脱台帳行き）。

期待される文字数（推奨案 `Ncold`＝17字で生成した場合）:

| 腕ID | 文字数 |
|---|---|
| `O-Ncold` / `Ncold-O` | 268 + 17 + 2 = **287** |
| `Onull-Ncold` | 273 + 17 + 2 = **292** |
| `Osec-Ncold` | 290 + 17 + 2 = **309** |

## 7. 生成手順（決定的・器材の契約）

`tools/` に小さな生成器（例: `build_combo_arms.py`）を置き、次を満たすこと。引数を取らず、表を内蔵し、実行のたびに同一バイトを出す。

1. §5の素材SHAを照合（不一致で `exit`）。
2. §3.1の式で4本を生成し `arms/panel/` に書き出す。
3. §6 (a)〜(f) を検査し、1つでも落ちたら書き出しを取り消して `exit`。
4. 腕ID・素材SHA・生成物SHA・文字数の表を標準出力に印字（この出力を FREEZE-RECORD に貼る）。

**生成器のSHAも記帳する。** 生成器を後から変更した場合、生成物を作り直して SHA が一致することを確認するまで、その腕を用いた走行を行わない。

## 8. 起草者の所見（裁定は登録者）

- **順序反転対の解釈には非対称がある。** `O-Ncold` では冷徹一行が「最後に読む指示」の位置に来て、`Ncold-O` では存在論的前置き（268字）が後に来る。位置効果と用量差（17字 対 268字）が同時に反転するため、「後置きが勝つ」という読みは**位置と用量を分離できない**。分離を望むなら、`Nk`（16字・存在論寄りの一行）を用いた `Nk-Ncold` / `Ncold-Nk` の対（用量ほぼ同等・位置のみ反転）を足すのが最小の追加である。採否は登録者裁定。加えない場合は、限界としてこの非対称を結果文書に先に書くことを勧める。
- **`Onull-Ncold` と `Osec-Ncold` はどちらも「何らかの前置きの後に冷徹」の統制だが、意味が違う。** `Onull` は存在論的主張も慈悲も持たない（書き手・読みやすさの語）ため「長い前置きがあること」の統制であり、`Osec` は存在論的語彙のみを世俗語に置換した対照であるため「仏教語彙か否か」の統制である。結果表では二つを別の行として扱い、まとめて「統制」と呼ばないこと。
