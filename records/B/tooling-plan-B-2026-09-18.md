## 2. 合成データで発火させる札（全経路・`synth_B.py`）

**器材は凍結の前に、合成データで札の全経路を一度ずつ以上発火させる**（段階 A の型・草案8B §2.9）。下の 15 経路を、合成データで一つずつ作って発火を確かめ、記録に残す。

| 札・分岐 | 発火の条件 |
|---|---|
| 確証 | 両側 Fisher が Holm の初段以下で、どの門にも落ちない |
| 判定不能（検閲） | 両腕とも床未満、または両腕とも天井超 |
| 判定保留（書式外転位） | 腕の間の書式外率の差が門を超える |
| 判定保留（refuse 転位・差） | 腕の間の refuse 率の差が門を超える |
| 判定保留（refuse 転位） | 答えた分母で向きが保たれない、または名目有意を失う |
| 判定保留（様式転位） | 応答様式の差が保留の帯を超える |
| 注（様式） | 応答様式の差が注の帯を超え、保留の帯以下 |
| 判定不能（品質床） | 選定後の品質床に落ちた腕を含む |
| 非有意 | どの門にも落ちず、Holm を通らない |
| 登録された向きと逆 | 札が立ったが、封印した予想符号と逆 |
| 門1 を閉じる | 品質床の選定の段に合格する候補が無い |
| 全候補が非正 | 操作有効性の点推定が全候補で零以下（登録者に上げる） |
| 同点の割り方 | 点推定が同じ候補が複数（無作為に割る） |
| 床・天井で選定から外す | 候補の両腕が床または天井 |
| 決定性の不一致 | 主位置の活性が二度の保存で一致しない（走行を止める） |

## 3. 順（先に決める）

1. `runs_B.py`（共有の読み口）→ 2. `analyze_B.py`（集計と札）→ 3. `synth_B.py`（合成データ・全経路の発火）→ 4. `integrity_B.py`・`sample_inspection_B.py` → 5. `direction_B.py`・`steer_B.py`（GPU 側）→ 6. `boot_stageB.py` → 7. 報告の雛形 → 8. `freeze_B.py`。

## 4. この段でしないこと（先に書く）

- **実機で走らせること**。GPU が手元に無いので、方向の抽出と加減の器は書いて型を検査するところまでで、実際の活性は作らない（Colab の段で走らせる）。
- **品質床の課題を選ぶこと**（裁定 D66・登録者が凍結の前に一つ選ぶ）。器は課題の断片を外から受け取る形にする。
- **予想符号を封印すること**（凍結の段・データを一つも見る前）。器は封印の欄を持つだけにする。
- **正本を変えること**。器材の整備で正本の不足が見つかったら、正本を直す前に記録に残し、設計の変更として登録者に上げる。

## 5. 予想（器材の段で見つかるもの）

- 正本の不足（器を書くと初めて分かる欠け）が**数件見つかる**: 高。とくに品質床の走行の形と、走行キーの粒度。
- 合成データで全経路が一度で通る: 低〜中（段階 A では数回の往復が要った）。
- 器材の実装検分で、系統外の目から新しい所見が出る: 高（設計の検分の二段目でも、系統外だけが挙げた所見が二件あった）。
