## 2. 指摘（重大 → 軽微）

### 重大（凍結を止めるか、凍結前に閉じる）

**M1. 凍結確認直前の正本バイトが、草案8 ヘッダの SHA16 と器材が読むキー集合と同一であることの再確認が、この票では閉じきれていない。**  
生成器 v2.4 は `confirm_rule.type='two_scale_iut_holm_maxp'`、`labels`、`label_combo_table`（`combo_rows`）、`holm_scope` 相当の `level`／`holm_rule`、`p_star_if_mismatch`、`python_control` を書く。草案8 ヘッダは正本 SHA16 `9A679F0931EF8034`。合成・格子・転記行 D も p* の Holm で数えている。一方、この検分の raw 読取の一経路では `confirm_rule.type` が `two_scale_iut_holm`（maxp なし）・`labels`／`label_combo_table` が無い形に見えた。器材 v1.2 は `CR['labels']` と `pt_slope['p_star_if_mismatch']` を読むため、古い正本では自己検査が KeyError になる。procedure 10 の「直前に正本・格子・転記行・本文・lint を再生成」が、この不一致を閉じる手続きである。再生成後の SHA を草案ヘッダと凍結記録に書き、`python tools/confirm_A.py --selftest` の PASS を凍結記録に残す。これが無い凍結は、草案8 と器材が別の正本を指しうる。[[6]](https://raw.githubusercontent.com/YutaKusumi/ontology-preamble-4b/main/tools/make_contrasts_A.py)

**M2. 既定の凍結前三项は未了（門0.5・Firth 一致検査・判定器の範囲）。** 草案8 §2.14 と依頼文のとおり。Firth 不合格（R／logistf 導入失敗を含む）は凍結を止めると正本 `firth_check` が書く。判定器の範囲は登録者の確定待ち。自動保留規則は置かない（D13）ので、範囲外機種は読み条項 (xv) と転記行 O の幅だけが残る。範囲を「全機種」から「4B と 32B」に絞るなら、絞った事実を凍結記録に書く。

**M3. 運用の解釈は「確認待ち」。** 閾値・帯は変えていない。ただし項 25 `sessions.commit_rule` は実装検分 P82（本走行）をデータ相全体に広げ、項 24 `calibration.incomplete_rule` は n_ok&lt;n の校正腕を未判定にする。帯の pt は動かないが、走らせ方と合格の数え方が決まる。確認の採否を凍結記録に残さないと、起動器の現行（40 桁必須・不完全は判定しない）が正本の確定文言かどうかが凍結後に争点になる。

### 中（規則の読みとして偏りがあるが、登録済みの仮定）

**C1. 「測れた」の独立仮定は、閾値 0.8 の近傍で「測れた」側に働く。**  
`at_least_one(ps)=1−∏(1−p_i)`。転記行 D 自身が「『少なくとも一本』だけが対比の独立の仮定に依る（腕を共有する対比は独立ではない）」と書く。同じ機種重み・同じ対照腕を共有する 5 場面は正の依存が入りうる。固定マージンでは和集合は独立より小さくなりうるので、独立式は P(少なくとも一本) を大きくし、`≥0.8` を満たす効果種を増やしうる。  
実基底の印字例：Onull~N・対照下降で少なくとも一本 **0.764**（閾値 0.8 の下）、一定では **0.973**。0.764 は独立を外すとさらに下がりうる。外した規模を戻さない・4B 欠測を 0 にする細目は「測れた」を減らす側。差し引きは、0.8 近傍だけ独立式が効く。観測効果量は使っていない（D11 どおり）。規則を変えるなら登録者裁定。実装は正本の式どおり。

**C2. 合成検査の期待は判定ロジックの完全な別実装ではない。** 行 id の符号化は `confirm_A.row_id` を使う。統計的な発火（clause／star）は配置の型から置き、集計器の出力と突合する。変異 M4・M5 が confirm_A 側を壊して不一致を出すので、refuse 理由と様式 (a) については循環を破っている。`row_id` の文字列規約そのものの誤りは、期待と実装が同じ関数なら見逃す。自己検査の 52 行発火がこの穴を狭める。追加の独立実装は置いていない。

**C3. 起動器は Colab 実機未走行。** DRY は P75–P83・D24 の枝を通す。GPU 名、vLLM `num_preemptions` の前後差、snapshot ディレクトリ名と 40 桁 SHA の一致は実機でしか落ちない。門0.5 が凍結前に実機を通る設計なので、門0.5 の失敗は凍結停止になる。門0.5 合格をもって起動器の実機経路が閉じたとみなすなら、その旨を凍結記録に書く。

## 4. 判定

**条件つき。** 差し戻し（規則の再設計）ではない。凍結可能水準でもない。

### 凍結の前に満たすべき条件
1. 門0.5 を走らせ、合否二分岐だけを確定する（族・n・閾値・帯は動かさない）。起動器の実機経路（重み SHA、校正腕の件数、終了コード）がここで落ちれば凍結しない。  
2. Firth の一致検査を正本 `firth_check` の合否規則で走らせ、不合格なら凍結しない。  
3. 判定器の妥当性の範囲を登録者が確定し、絞る場合は機種名を凍結記録に書く。自動保留は足さない。  
4. 運用の解釈 28 項を確認する。とくに 24（不完全校正は未判定）と 25（データ相の固定コミット）。否なら正本・起動器・合成を直してから凍結する。  
5. 凍結確認の直前に正本・格子・転記行・本文・lint を再生成し、SHA16 をヘッダとマニフェストで一致させ、`confirm_A.py --selftest` の PASS を記録する。

### 凍結の後に逸脱として記帳すれば足りる注意
- 測れた効果種の「少なくとも一本」は場面独立。0.8 近傍（転記行 D の Onull~N 下降 0.764 など）では分類が仮定に依存する。式を変えるなら裁定。  
- `p_β < α` と `≤` の差、`--B-measurable`、`gate2_shrink=True` の口、合成ファイル名の日付、門0.5 の HEAD と凍結 SHA の差。  
- 起動器の vLLM 計測値名・snapshot 名は門0.5 で実測し、名が正本の記帳と違えば逸脱。  
- 反映確かめの系統内 COI と事後の事前登録。

条件 1–5 を満たせば、札の二段・D16 の縮小・D10 の p* Holm・D11 の選択規則の実装は、草案8 の文言と 52 行の表と合成 15 走の発火で一つの札に決まる形になっている。閾値と帯をこの検分で動かす理由は無い。
