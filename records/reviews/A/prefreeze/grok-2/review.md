## 指摘（重大）

### 1. pt 差の傾きの正規近似は、同じ Holm 初段（α/35）で使う水準になっていない（重点 1）

正本 `confirm_rule.pt_slope`：重み付き最小二乗、`q=(k+0.5)/(n+1)`、`se=√(1/Σw(z−z̄)²)`、正規近似、水準は「β₃ を棄却した Holm の調整水準」（初段なら α/35）。`power_grid_A.py` は `z_h1 = norm.isf(α/35/2)`（約 3.38）で札 D1 を数えている。[[2]](https://raw.githubusercontent.com/YutaKusumi/ontology-preamble-4b/main/design/contrasts-A.json)

残存規模は 3〜6。傾きの自由度数は残存−2。正規の臨界 3.38 に対し、両側 0.0014 の t 臨界は残存 6（df=4）でおよそ 7〜8、残存 3（df=1）ではさらに大きい。登録した区間は、残存 6 でも名目の α/35 より狭く、0 を含まない側に出やすい。

転記行 D の中間・Δ=15 pt の札 D1 初段 0.941 は、この z 臨界での数である。残存規模数ごとの内訳は格子に無い。判定不能（残存 3 未満）の隣の残存 3 ちょうどが、D1 の検出側の主たる落ち方になる配置は印字されていない。

二尺度の IUT の形（両方棄却のときだけ確証）は一義。足りないのは、小さい α で正規近似を使う登録が、残存 3〜6 の点数に対して水準を保つことの計算である。

### 2. `label_precedence` は配列のままでは一つの札に落ちない（重点 1・10）

正本の配列は先頭が「非有意」。注は「β₃ が Holm で棄却されない対比は非有意（判定不能を除く）。棄却された対比には列の順に最初に当てはまる札を一つ」と二段に分けている。配列を first-match すると「非有意」が常に先に当たる。

「判定不能」は棄却後の枝に書いてある。`one()` は残存 3 未満で PPLRT を打たずに `undecidable` を返す。実装は判定不能を検定の前に置く必要があり、注の枝と配列の順が一致しない。

さらに、棄却後の順は 解釈条項 → 尺度のみ → refuse → 様式 → 環境 → 確証。尺度のみが refuse／様式／環境より前なので、β₃ が Holm で棄却され pt 傾きが条件を満たさない対比は、refuse 転位や環境保留が立っていても「記述（対数オッズ尺度でのみ）」になる。refuse 門は「Holm 前 p<0.05 にのみ適用」、様式門は `applies_to: confirmed_only`。様式は確証の後にしか作用しないと読みうるのに、優先順では確証の前にある。

札を一つに決める規則は注を読めば書ける。正本の配列と `applies_to` をその注と同じ手続きに書き換えないと、未整備の `analyze_A.py` が二通りに実装できる。

### 3. 解釈条項を受け入れた到達の偏りは、効果種 × 場面に固定されている（重点 2）

転記行 D 実基底（22 本・B=1000）：対照が 32B−4B で ±20 pt 動くと、解釈条項が当てはめの 0.5 以上で発火する対比は 12 本／14 本。札 D1 初段の平均は 0.254／0.273。一定なら発火 8 本・平均 0.537。

転記行 C の「片腕が既に閾外」6 本はすべて N2／S1／SK の Onull−N と Lneg−Onull。4B の既測で対照または処置が床・天井にあり、もう 1 規模が閾外に出れば条項が発火する。S1 の N は 400/400、Lneg は 320/320。SK の N は 400/400、Lneg は 316/320。

既測のある 22 本で条項を生きやすいのは、中間域の O-Ncold 系に寄る。Odose1／Odosehalf 系 10 本と N2 の Ncold 系 3 本は格子の実基底に載っていない。問い（機種の並びで差がどう変わるか）には、並記表で全 35 を札つきで出す、という答え方は雛形にある。確証札だけを読むと、天井側の効果種 × 場面が系統的に抜ける。

### 4. 集計器が未整備のまま、札の全分岐を踏む表が正本に無い（重点 10）

転記行 J の未整備：`analyze_A.py`・`synth_A.py`・`gate_A.py`・`identity_screen_A.py`・`build_report_A.py`・`freeze_A.py` ほか。手順表の凍結ゲートは門0.5・Firth 一致・判定器の範囲であり、集計器の合成発火は番号付き手順に入っていない。

段階 F は全組合せ 288 行を正本に置き、synth が発火可能行を踏んだ。A の D1 は β₃ × pt 傾き × 解釈 × refuse (a)(b)(c)(d) × 様式 × 環境 × 残存 3〜6 で、優先順の衝突（指摘 2）は合成データでないと現れない。JSON に規則を書いたことで、実装の検分が止まっている。

### 5. 撤退条件は不合格が主経路のまま API 既測を参照する（重点 9・3）

§2.8：校正帯は合格枝＝API、不合格枝＝手元初点、と二分してある。同じ節の撤退条件は「パイロット n=40・15 pt・合格枝と同じ API 既測」。転記行 I の発火 X≤32 は API 0.975 に対する片側。

門0 の下見で不合格の主因は N（−21.7／−24.2 pt）。Ncold は −2.5 pt で 15 pt の内側。数値の見込みとしては発火しにくい。規則としては、合否二分岐を足した内側に、パイロットの撤退だけ合格枝の参照が残っている。不合格時に手元の Ncold 率が API と 15 pt 超ずれた場合、器の異常としてセッションを再走する基準が、測っていないスタックの率になる。

## 指摘（中）

### 6. 環境帯の多重は JSON と本文で粒度が違う（重点 3）

正本 `environment_band.selection_rule`：期待誤保留は「対比の二腕 × 橋の二機種のいずれか」。`grid_M()` は `nb=2` を指数に入れ、12 pt で期待 0.88≤1。登録値は選択規則と一致する。

草案 §2.4 は「橋の環境差が環境帯を超えた腕を含む対比」とだけ書く。機種が 4B と 8B の二点であることは §2.1 と (xiii) にある。本文だけ読むと、腕 13 に一度だけ当てる実装が通る。正本が正なら本文を正本の一文に揃える。

残存規模が環境切替（4B と 8B の間）の片側にしか無い対比も保留。残存の下限は 3 なので、残ったのが 0.6B・1.7B・4B だけ、または 8B・14B・32B だけのときに発火する。検閲・錨帯除外と重なると、解釈条項とは別経路で D1 が落ちる。格子の実基底の行は環境保留を含まない。

### 7. refuse 門の格子は Lneg の既測を覆わない（重点 6）

転記行 D の refuse は四配置。転位なしは refuse 0.10 または 0.30 一定。転位ありは 0.05→0.35。Lneg の API 既測は N1 140/320、N2 201/320。門0 手元は A100 26/40。答えた分母の n_ok≥30 は n=200 では足りうるが、端の 15 pt 超（条件 (c)）が規模で動きやすい。Lneg−Onull は解釈条項の 6 本とも重なる。refuse 門のあとの札 D1 を Lneg の基底で出した行が無い。

符号 0 は不一致。答えた分母の再フィットは残存を数え直す。ここは一義。

### 8. Firth の許容差は走らせる前の登録として狭い（重点 5）

正本 `firth_check`：係数 1e-06、罰則付き対数尤度 1e-06、PLR 統計量 1e-05。R は `lconv/gconv/xconv=1e-12`、`maxit=1000`。`firth.py` の既定は `max_iter=200`・`tol=1e-9`・`gtol=1e-7`。比べる量（係数・罰則付き ll・統計量）と、不合格なら凍結を止めて許容差を動かさない、は一義。

合成の第三配置は床 0.03。分離近傍で係数の絶対差 1e-06 は、BLAS と収束判定の差だけで不合格になりうる。合否規則として妥当なのは「動かすな」の側であって、1e-06 が Python／R で常に内側に入ることの根拠は未実行のまま最終確認で確定している。

`firth.py` v2 の修正スコア・全模型罰則の制約・logaddexp・step-halving・converged の意味は、自己検査の項目として書かれている。logistf との一致は未実行。

### 9. 転記行 D の Δ=0 行の「棄却率」0.057 は札 D1 初段ではない（重点 6）

対照中間・Δ=0・d0=0 の 0.057 は、格子見出しの p<α（名目）に近い。Holm 初段の α/35 でも、札 D1 初段でもない。同じ転記行の検出力は「札 D1（初段）」と書いてある。帰無の行だけ指標名が落ちている。FWER の実サイズをこの 0.057 で読む経路が残る。

「少なくとも 1 本」は独立を仮定、と書いてある。期待本数の和は線形なので独立は要らない。確率のほうだけ仮定が要る。

### 10. 報告雛形は順序を固定しているが、打ち込んでよい SHA の範囲が正本とずれている（重点 7）

雛形は節順・並記表・札 × 状況の読み文・先頭の門0.5 と上向き確証の位置を、率の前に固定している。`typed_numbers` は日付・SHA16・費用実績・逸脱番号・雛形 SHA16。雛形本文は SHA-256〔記帳値〕も含む（封印予想）。正本 `report_rules.typed_numbers` に SHA-256 が無い。組み立て器が雛形の SHA-256 を未登録の数として止めるか、通すかが未整備の `report_lint.py` に残る。

読み文の表は件数だけ機械転記で、文言は先置。ここは率を見てから文言を選ぶ形になっていない。

### 11. `numbers_lint` は値の集合検査であり、同じ数が別の意味で使われても止まない（重点 8）

除外マスクは SHA・日付・版・機種名 B・場面名。§6 は検査しない。未登録 0 は「§1〜5 に CONST 外の数字が無い」まで。15 は様式注・撤退・床のセル列、12 は錨帯・環境帯・同一性の最大、5 は校正帯と平均差、3 は残存下限と効果種、に共用される。派生した数を見逃す経路は、マスクの広さより、定数の衝突のほう。正本の説明文 269 を見ているのは、キーを除外していない（文字列値だけ見る）ので、説明文に書いた数の抜けには当たる。

## 判定

**条件つき。** 凍結可能水準ではない。差し戻して族や条項をやり直す対象でもない。草案2 で空だった系列 p・不合格枝の校正初点・両腕条件の一本化・m 固定は、正本と転記行に落ちている。残っているのは、D1 を小さい α で実装するときの推定量と、札の優先順の手続きと、集計器が踏んでいない分岐である。

凍結前に本文と正本で一つに固定するもの：

1. pt 差の傾き：正規のままにするなら、残存 k=3,4,5,6 ごとに名目 α/35 での実サイズを格子に足す。t（df=k−2）にするなら臨界と転記行 D を作り直す。残存 k 別の札 D1 率を印字する。
2. `label_precedence`：判定不能を検定前に置く。Holm 非棄却→非有意。Holm 棄却後の順から「非有意」と「判定不能」を外す。尺度のみと refuse／様式／環境の前後を一文で決める。`style_gate.applies_to` をその順に合わせる。
3. 解釈条項は変えない、を維持するなら、効果種 × 場面で条項が発火しやすい 6 本（転記行 C）を雛形の並記表の注の定型に先置する。Odose 系 13 本は実基底なし、と検出域の節に書く。
4. `analyze_A.py` と `synth_A.py`：優先順の発火可能行の表を正本に置き、合成で全行を一度踏む。未整備のまま凍結しない。
5. 撤退条件の参照系列を、校正と同じ合否二分岐にする（不合格なら手元のパイロット校正腕、または撤退を不合格枝では使わない）。
6. 環境帯の「二機種」を草案 §2.4 に正本の逐語で書く。
7. 転記行 D の Δ=0 行に、名目 β₃／Holm 初段 β₃／札 D1 初段を三つ並べる。
8. Firth の許容差を走らせる。1e-06 で不合格なら、原因を記帳して凍結を止める（規則どおり）。通すために許容差を動かさない。
9. `report_rules.typed_numbers` に封印予想の SHA-256 を入れるか、雛形から外す。

1・2・4 が未固定のまま凍結すると、集計器の札が正本から一意に出ない。3 と 5 は測定の残る範囲の話で、条項を変えない決定とは独立に、報告の先置だけ直せば足りる。
