### 1.3 Firth（重点5）

`python tools/firth.py --selftest` を実走し、**PASS を再現**しました（集約形とベルヌーイ行の統計量の差 4.55e-13・BFGS 直接最大化との罰則付き対数尤度の差 ≤2.6e-12・帰無の棄却率 中間 0.0500／上昇 0.0440／床 0.0505／天井 0.0495・分離 4 型で収束・あふれ回避・converged の判定）。

構成は Firth (1993)・Heinze & Schemper (2002) と一致します。集約形の修正スコア `U = X'(y − mμ + h(0.5−μ))`、`h_i = m_iμ_i(1−μ_i)x_i'I⁻¹x_i` は、同じ行を m 個のベルヌーイ行に展開したときの Σh_j(0.5−μ) と厳密に等しく（自己検査 1 がこれを 1e-13 で示しています）、制約付き当てはめが全模型の罰則 ½log|X'WX| を最大化する型も文献どおりです。

**許容差の妥当性**（重点5 の問い）を数値で確かめました。firth.py の既定停止（gtol=1e-7）と高精度解（gtol=tol=1e-14・max_iter=2000）の差は、本設計型の三配置で β が最大 1.5e-10・罰則付き対数尤度が 2.3e-13（|ll|≈1250〜1625）・PPLRT 統計量が 9.1e-13。**登録許容差（係数 1e-6・対数尤度 1e-6・統計量 1e-5）は firth.py 自身の数値雑音より 3〜4 桁上**にあり、走らせる前の登録として無理がありません。また `firth_check_A.py` は合成データをベルヌーイ行の CSV で書き出すので、R 側も同じ展開形を読みます（集約形は自己検査 1 が橋渡しする）。統計量を比べる設計は、制約付き当てはめの流儀の違い（追い問い V12 の 10.07 対 15.15）が起きれば必ず外れる形になっていて、検査として効きます。

## 2. 指摘

### 【重大】

**重1. 集計器が存在しないまま凍結の手順が組まれている（重点10）**

転記行 J の未整備は 12 器: `boot_stageA.py`・`identity_screen_A.py`・`analyze_A.py`・`calib_band_A.py`・`gate_A.py`・`control_chart_A.py`・`integrity_A.py`・`sample_inspection_A.py`・`synth_A.py`・`build_report_A.py`・`report_lint.py`・`freeze_A.py`。転記行 J は「**凍結前に整備し dry-run と合成データで検査**」と書いていますが、

- §5「凍結の前に残る手順」: 検分 → 門0.5 → Firth 一致検査 → 判定器の範囲の確定 → 登録者の凍結確認 → 凍結。**器材の整備が入っていない。**
- 正本 `procedure`: 1 門0 → 2 検分 → 3 門0.5 → 4 Firth → 5 凍結 → 6 パイロット → … → 13 集計。**同じく入っていない。**

三者が食い違います。帰結は二つあります。(i) `procedure` 3 の門0.5 は `identity_screen_A.py` を、5 の凍結は `freeze_A.py` を要しますが、どちらも未整備で、手順表はそれを整備する場所を持ちません。(ii) より重いのは、**`analyze_A.py` が凍結の後・パイロットの率が出た後に書かれる経路が開いている**ことです。二尺度の規則・札の優先順・pt 傾きの推定量・refuse 門の四条件は、いま正本に文字列としてはありますが、実装はまだありません。§7 の「確認していないこと」は「札の優先順と二尺度の規則の実装は合成データで未検査」と正しく書いていますが、それを凍結前に閉じる手順が無いため、この文は凍結後も真のままになります。事前登録として、**規則の文字列だけを凍結し実装を後に回すのは、いま直せる穴**です。

**直し**: §5 と正本 `procedure` に「器材の整備 → `synth_A.py` で合成データに全分岐（8 札 × 各規則 × 検閲・錨帯・環境・refuse・様式）を発火させる → 器材の SHA16 を凍結マニフェストに入れる」を、門0.5 の前（identity_screen）と凍結の前（analyze・gate・calib・report_lint・freeze）に置く。

**重2. `label_precedence` の列が第一適合で実装できない（重点1）**

正本 `confirm_rule.label_precedence` は
`["非有意","判定不能（検閲・門2）","記述（解釈条項）","記述（対数オッズ尺度でのみ）","判定保留（refuse 転位）","判定保留（様式転位）","判定保留（環境）","確証"]`
で、`precedence_note` は「β₃ が Holm で棄却されない対比は非有意（**判定不能を除く**）。棄却された対比には列の順に最初に当てはまる札を一つだけ付ける」。

散文は正しいのですが、**機械可読の列は「非有意」が先頭にあるため、「列の順に最初に当てはまる」をそのまま実装すると、残存規模 2 の対比（β₃ が計算できない＝棄却されない）に「非有意」が付きます**。実験で確認しました（`for lab in label_precedence: if applies(lab): return lab` → 非有意）。§2.4 と `precedence_note` が定めるのは「判定不能（検閲・門2）」です。読み条項 (iii)「検閲セル…を『効果なし』と読まない」を、器が正面から破る配線になります。

`analyze_A.py` が未整備の今なら一行で直せます。**直し**: 列から「非有意」を外して既定札にする（または列の先頭を「判定不能（検閲・門2）」にし、「非有意」を末尾の既定にする）。あわせて `precedence_note` に「列は棄却された対比にのみ適用する」と書く。

### 【中】

**中3. 転記行 D の「尺度依存の穴」の行は、見出しの条件を満たしていない（重点6）**

転記行 D は「**pt 差が全規模で一定（Δ=0）の配置での札**」として、対照が上昇（0.3→0.9）の d0=5／10／15／20／30 pt を並べます。しかし `treat()` は `np.clip(raw, 0.001, 0.999)` を掛けるので、格子の D 表の切り詰め列を見ると d0=10／15／20 pt はいずれも **切り詰め 1〜2 規模**です。実際の真の pt 差を印字すると、d0=15 pt の行は `[0.15, 0.15, 0.15, 0.15, 0.15, 0.099]`——**上端で 5 pt 縮んでおり、pt 差は一定ではありません**。真の pt 傾きが負・β₃ が正になるため向きの条件が外れ、札 D1 が 0.001 に落ちます。d0=20 pt の行で札草案4 が 0.008 と、d0=15 pt の 0.376 より小さくなる非単調も、切り詰めと飽和の産物です。

結論（D1 が尺度依存を抑える）は変わりません——切り詰めの無い配置で測り直すと札 D1 初段は 0.000〜0.001 で頭打ち（§1.4(b)）——が、**本文が根拠として引いている行は、本文が書いている配置ではありません**。逆向きにも歪みます: 「対照が動き、かつ真の効果がある」行は本文に一つも無く、格子の該当行（ctrl_rising d0=0.05・Δ=0.10 で草案4 初段 0.788 → D1 初段 0.425）は切り詰めのせいで実効 Δ がほぼ 0 になった行なので、これを読むと D1 が大きな検出力を失うように見えます。切り詰めの無い配置では損失は 0.023 以下です（§1.4(c)）。

**直し**: `PATTERNS` に余白のある型（例 `ctrl_rising_080 = linspace(0.3, 0.8, 6)`・`ctrl_falling_080`）を足し、転記行 D の「穴」と「対照が動く × 効果あり」はその行から引く。最低限、転記行 D の本文に各行の**切り詰め規模を印字**する（いまは「全規模が切り詰められて外した行 0」しか出ていません）。

**中4. 橋のセッションに校正腕が無い（重点3・4）**

`plan_bridge` は `tr = 13 × 200` だけで、`sess * n_cal` の項を持ちません。転記行 F の上界のセッションは機種 8＋橋 2＝**10** ですが、転記行 A の校正腕は「転記行 F の上界のセッション数の合計 **8**」＝3,200 試行です。§2.8 は「校正腕＝… を機種のセッションごとに 1 回」で、橋の走行は別の GPU の別セッションです。

数としては 800 試行の差ですが、効く場所が悪い。**橋は環境差を測るための走行で、そこだけ器の点検が落ちる**と、セッション水準の器の異常が環境差と分離できません。環境帯（12 pt）を超えた腕は確証を保留するので、器の異常が保留に化けます。**直し**: 橋のセッションにも校正腕を置く（+800 試行・約 +2 ユニット）か、置かない理由と帰結を §2.8 に一行で書く。

**中5. 同時要求数が同じ環境値の中で変わる（重点4）**

正本 `environments` は 14B を「A100 80GB・同時 24／40GB のとき同時 20」、8B を「同時 24／40GB でも 24」としています。§2.1 は「40GB が割り当てられたセッションでは 8B・14B だけを走らせ（14B は同時 20）」。つまり **14B は、割り当てられた GPU によってセッションごとに同時要求数が 24 と 20 で変わりうる**。一方、§2.4 の環境ダミーは L4／A100／第三 の三値で、この差は入りません。橋も同時要求数の差を測りません（橋 4B は A100 側 24、橋 8B は L4 側 12 で、いずれも「環境の差」と「同時要求数の差」が交絡しています）。

vLLM のバッチ構成は生成に影響しうるので、これは測定側の変数です。§2.12 が試行ごとに同時要求数を記録するのは良いのですが、読み条項 (xiii) と §4「果たさないこと」に対応する文言がありません。**直し**: (a) 機種ごとに同時要求数を一つに固定する（14B は常に 20）か、(b) (xiii) に「同じ環境値の中で同時要求数が変わりうる。同時要求数の差は測っていない」を足し、§4 に「同時要求数の効果を環境の効果から分離したと書かない」を足す。(a) のほうが安く、費用への影響は上界で 14B が 43.0 → 約 51 ユニット（合計 251 → 259）です。

**中6. 不合格枝で撤退条件だけが API 基底のまま（重点9）**

正本 `calibration.band_fail` は「初点＝本走行の最初のセッションの校正腕」に直りました（裁定 D2）。しかし `calibration.withdrawal.reference` は **「band_pass と同じ API 既測の率」** のままです。§0-3 と §2.9 は「不合格が主経路」と見込んでいるので、**主経路では、撤退条件だけが設計自身が外れていると見込む基底に固定されます**。

数で言うと、撤退条件は パイロット n=40 で X≤32（0.800）のとき発火します。手元の真の Ncold 率が 0.90 なら発火率 0.042、0.85 なら 0.244（転記行 I の検出側の行）。帰結は「当該セッションを再走・なお外れれば器の異常として記帳し確証札に注」なので、**手元と API の系統差が、全機種の確証札に付く注に化けます**。

**直し**: `withdrawal.reference` に不合格枝の分岐を書く（合格枝＝API 既測／不合格枝＝門0.5 の手元 Ncold×N1 を参照、または撤退条件を測定不能率だけに畳む）。校正帯と同じ形の二分岐を置けば済みます。

**中7. 確証に到達できない対比の一覧が、凍結前に計算できるのに本文にも雛形にも無い（重点2）**

転記行 D の実基底の行は最大・中央値・平均・本数だけを載せています。格子の DR 表（既測基底 22 本 × 三型 × Δ）から対比ごとに引くと、Δ=±15 pt でも三型のいずれでも札 D1 初段が 0.05 未満の対比が **5 本**あります:

`N2:Lneg~Onull`・`S1:Onull~N`・`S1:Lneg~Onull`・`SK:Onull~N`・`SK:Lneg~Onull`（いずれも三型とも 0.000）

効果種でまとめると、Δ=±15 pt での札 D1 初段の平均と「0.05 未満の場面数」は

| 効果種 | 一定 | 上昇（+20 pt） | 下降（−20 pt） |
|---|---|---|---|
| Onull−N | 0.287（3/5 が盲） | 0.215（3/5） | 0.199（3/5） |
| Lneg−Onull | 0.381（3/5） | 0.386（3/5） | 0.379（3/5） |
| Onull-Ncold−Onull | 0.391（1/4） | 0.108（1/4） | 0.000（**4/4**） |
| O-Ncold−Osec-Ncold | 0.931（0/4） | 0.538（1/4） | 0.640（0/4） |
| O-Ncold−Onull-Ncold | 0.796（0/4） | 0.000（**4/4**） | 0.138（2/4） |

期待本数は 一定 11.81・上昇 5.59・下降 6.00（対 Δ=0 の 0.015／0.003／0.005）。つまり**族全体としては働くが、どの効果種が見えるかは対照の動き方で入れ替わり、Onull−N と Lneg−Onull は三型とも半分以上が盲**です。加えて既測基底の無い 13 本（Odose 系 10 本を含む）は格子に載っておらず、検出域の見込みがありません。

これは設計の欠陥ではなく（登録者最終確認で受け入れ済み）、**報告での読み違いを止める材料が先置されていない**という指摘です。報告に「確証 0 本」が出たとき、5 本＋13 本＝18 本は初めから確証に届く見込みが無かった、という事実が同じ画面に無いと、(iii) と (viii) だけでは持ちません。**直し**: 報告雛形 §0-6 か §1 に「凍結時の見込みで、既測基底のある 22 本のうち〔 〕本は三型のいずれでも Δ=±15 pt の札 D1 初段が 0.05 未満・既測基底の無い〔 〕本は検出域の見込みを持たない」の欄を足し、転記行 D にその 2 数を印字する。

**中8. numbers_lint は「登録済みの別の定数への取り違え」を通す（重点8）**

実験しました。

- 本文の「帯は **12 pt**」を「**15 pt**」に書き換える → 未登録 0・**exit 0（通過）**。15 は `style_gate.note_pt`・`refuse_drift_pt`・`withdrawal.band_pt` として登録済みだからです。
- 「30% 超で測定不能」を「40% 超」に書き換える → 同じく**通過**（40 は `pilot_n`）。
- 「期待 11.81 本」を足す → 未登録 2・**exit 1（検出）**。

器の性格（登録の有無であって値の正しさではない）どおりの挙動で、器の欠陥ではありません。ただし §状態の「本文の数は設計定数と §6 の転記行のみで、`numbers_lint.py` が機械検査する」は、この限界を書いていないので、検査済み＝値が正しい、と読まれます。**直し**: lint の出力に「本器は数の登録の有無だけを見る。登録済みの別の定数への取り違えは検出しない」を一行入れる。値の照合が要るなら、帯・閾値・n の類だけは正本のキーを本文に埋め込む形（例 `censor.low`）にして展開する手もありますが、一行の開示で足ります。

**中9. `SKIP_STR` に確証規則の式のキーが入っている（重点8）**

`SKIP_STR` は `'weights', 'se', 'interval'` を含みます。これは `confirm_rule.pt_slope` の **推定量を定義している三つのキー**（`weights` = 「w＝1/Var・Var＝q_A(1−q_A)/n_A＋…・q＝(k＋0.5)/(n＋1)」など）です。除外の理由（式は数の並びなので誤検出が出る）は分かりますが、**器と正本が食い違うと最も高くつくのがこの三つの値（0.5 と 1）**で、そこだけ検査の外にあります。§1.4 のとおり今は `power_grid_A.one()` と一致していますが、`analyze_A.py` は未整備です。**直し**: 除外はキー名でなく「式であること」で判断する（`formula`・`cp_upper_rule` のようにキー名を式専用にする）か、`confirm_rule.pt_slope` に機械可読の欄（`continuity: 0.5`・`denominator_offset: 1`）を別に置いて lint と集計器の双方がそこを読む。

**中10. 感度閾値の結果を置く欄が報告雛形に無い（重点3・7）**

§2.5 は感度解析（0.03／0.08・0.97／0.92）を登録し、格子 DS は札の率まで出しています。振れは小さくありません——床の判定不能は 0.03/0.97 で 0.010、0.08/0.92 で **1.000**。主閾値 0.05/0.95 はこの急な区間の途中にあります。ところが報告雛形に「感度」の語が **0 回**で、§3 にも §4 の並記表にも感度の行がありません。主結果と感度が食い違ったときの書き方も §2.5 にありません。**直し**: 雛形 §4 に「感度閾値での札の内訳」の行を足し、§2.5 に「主閾値と感度閾値で札が変わった対比は一覧にし、主閾値の結果を主とする」を一行。

**中11. 様式門の一斉保留の見込みが凍結前に置かれていない（重点3）**

裁定 D6 でパイロット後に回した判断ですが、**転記行 G 自身が材料を持っています**: 既測の (b) JSON 直答率は N が N1 0.575・S1 1.000・S4 0.865・SK 1.000、O-Ncold が四場面とも 0.000。差は 57.5〜100 pt で、様式門の保留閾値 30 pt を大きく超えます。確証族で N を含むのは Onull−N の 5 対比です（Onull の (b) は既測なしなので確定はできません）。**直し**: 「Onull−N の 5 対比は様式差が 30 pt を超える見込みがある」を凍結前に §2.6 か転記行 G に書く。書いておかないと、報告で 5 本の様式転位が出たとき、それが所見として読まれます。

## 4. 判定

**条件つき。** 差し戻しにする理由はありません。草案4 で私が挙げた 12 件は、数の上でも器の上でも閉じており（§1.1）、新しく入った二尺度の規則・格子の無条件率・帯の選択規則・報告雛形・`numbers_lint` は、独立に計算し直した範囲ではすべて主張どおりに働いています。とくに二尺度の IUT は、私が切り詰めの無い配置で測り直しても、尺度依存の誤札を 0.001（初段）で頭打ちにし、検出力の代償が 0.023 以下でした。

凍結の前に次を閉じることを条件とします。

**必須（凍結物の一義性と実行可能性に関わる）**
1. **重2**: `label_precedence` から「非有意」を外して既定札にする（または列の先頭を判定不能にする）。`precedence_note` に「列は棄却された対比にのみ適用」を明記。
2. **重1**: §5 と正本 `procedure` に器材の整備を入れる。門0.5 の前に `identity_screen_A.py`、凍結の前に `analyze_A.py`・`gate_A.py`・`calib_band_A.py`・`control_chart_A.py`・`synth_A.py`・`report_lint.py`・`freeze_A.py`。`synth_A.py` で 8 札と各規則の全分岐を合成データで発火させ、器材の SHA16 を凍結マニフェストに入れる。
3. **中6**: `calibration.withdrawal.reference` に合否二分岐を入れる（不合格枝で API 基底を参照しない）。
4. **中5**: 同時要求数を機種ごとに一つに固定するか、(xiii) と §4 に同時要求数の交絡の文言を足す。
5. **中3**: 対照パターンに余白のある型（0.3→0.8 など）を足して格子を回し直し、転記行 D の「尺度依存の穴」と「対照が動く × 効果あり」をその行から引く。最低限、引用する行の切り詰め規模を印字する。

**望ましい（報告の読みに関わる・いずれも一行〜一欄）**
6. **中7**: 到達の見込みが 0.05 未満の対比の本数と、格子に載らない 13 本を、転記行 D と報告雛形 §0／§1 に先置する。
7. **中4**: 橋のセッションの校正腕（+800 試行・約 +2 ユニット）。
8. **中10**: 雛形に感度閾値の行、§2.5 に主結果と感度が食い違ったときの書き方。
9. **中11**: Onull−N の様式差の見込みを凍結前に書く。
10. **中8・中9**: lint の出力に限界を一行、`confirm_rule.pt_slope` の連続性補正を機械可読の欄に出す。
11. **軽12〜17**: B への参照、凍結直前の正本再生成と転記行・lint の作り直し、雛形への lint 適用の記録、転記行 N の検出側、停止規則の限定、「少なくとも 1 本」の独立の注。

1〜5 が閉じれば、凍結可能水準に達すると考えます。1〜2 は文字列の直しで済み、3〜5 は器材の再実行を伴いますが族・腕・n・閾値・帯の値は動きません。

なお、私が草案4 の検分で出した「約 411 ユニット」は、草案4 の転記行 L が示していた「32B は同時 8 なら載る」をそのまま入力に置いた数で、最大同時要求数を検査していませんでした。採否表 §5・§6 の訂正（上界 234.3、草案6 の登録値で 251.0）が正しく、私の数は取り下げます。
