## 2. 採否表の文言から離れた箇所（開示）

1. **P82 の固定のコミット**: 採否表は「本走行の相」を挙げたが、門2 と撤退条件の判定を決めるパイロット・撤退条件の再走・橋・錨反復もデータを作る相なので、起動器はそのすべてで固定のコミット（完全な SHA）を要り、既定の main を拒む（門0.5 と dry-run は main を許す）。正本 `sessions.commit_rule` に書き、運用の解釈の一覧に足した（登録者の確認を仰ぐ）。
2. **P77・P91 の校正腕の件数**: 件数（n_ok）が `calibration.n` に満たない校正腕は判定せず（no_data・incomplete）、起動器は機種の走行に進まずに止まり、次のセッション番号で校正腕から走らせ直す（`sessions.number_rule` に合わせた）。正本 `calibration.incomplete_rule` に書き、運用の解釈の一覧に足した（登録者の確認を仰ぐ）。
3. **D24 の初点の名乗り**: 名乗りは tag と機種で同定する（同じ機種は次のセッション番号でも始められる）。名乗った機種を走らせられない事情が出たときに名乗りを別の機種へ移すのは、登録者の判断で名乗りの記録を退避してから。Drive の同期は原子的でないので、並行のランタイムを同時に起こさない運用を前提にする。
4. **P79 のやり直しの回数**: `--redo-errors` は一つの走行キーで最大三回かけ、なおそろわなければ止まる。回数は登録の値ではなく起動器の定数。
5. **P96 の走査器の厳しさ**: 採否表の型（code span・括弧の年・章・番号・N GB・段 N）に加えて、英大文字に続く番号（D99・P96・札 D1 など）も、雛形と逐語で同じ行と機械の区画の外では違反にする。起草者が判定の番号を散文に書くときは、雛形の行か機械の区画に置く必要がある。
6. **P98 の枠の完全一致**: 見出しの名＝見出しの文字列のうち最初の全角括弧の前、と定め、各枠がちょうど一つあることを確かめる。
7. **P85 の入力の記録**: 入力の記録の正本 SHA16 が現在の正本と違えば止まる。校正帯の記録の未決の項（やり直し待ち・未完・逸脱・セッション記録なし・seed の不一致）と、撤退条件の判定が合格・再走の合格・器の異常のいずれでもないときは、記録の不足として止まる（`--allow-incomplete` は検査用）。
8. **P76 のラベルの形**: 奪取の場面の量は整数（奪取しない選択では零）とした（凍結パーサが整数を要るため）。正本 `judge_validity.extract.label` を合わせた。

## 3. 反映の途中で見つけた自分の誤り（自己修正）

1. 正本の追補の文言に数（「40 桁」）を書き、生成器の数の検査に掛かった。格子はすでにその正本で回り始めていたので止め、文言を「完全な SHA」に直してから格子を回し直した（古い正本の格子の出力は使っていない）。
2. 確証の共通関数 v1.2 で門2 の縮小の対比の区間を省いたため、集計器 v2 が縮小の対比の統計量を印字しようとして止まった。合成検査 v2 の走 13 で見つけ、集計器と組み立て器の印字の条件を段で絞った（縮小の対比は判定不能として統計量を印字しない）。見つけるまで、変異 M6 は見分けなかった扱いになっていた。
3. 走査器 v2 の最初の版は、英字の直後の数（D99）を拾わなかった（本文の数の検査の数の型が英字の直後を除く）。自己検査で見つけ、英大文字つきの番号の型を足した。そのため、組み立て器が区画の外に置く見出しの行から「採否表 P96」と「札 D1」を外した。
4. 起動器の DRY 検査の最初の期待は、合格枝の校正腕が帯の内に入ると置いていた。DRY のスタブの率では帯を超えるので、「帯を超えたら止まり、次のセッション番号でやり直す」経路を期待に書き直した（起動器は変えていない・二度目の DRY 検査で一致）。
5. 起動器 v2 の停止の案内を、はじめ「同じセッション番号で再開」と書きかけ、`sessions.number_rule` と食い違うことに書き上げる前に気づいて直した。
6. 集計器 v2 のパッチの一部（様式と門0.5 の記録の正本 SHA16 の欄の読み）を、パッチの文字列の不一致で一度当て損ね、別の置換で当てた。
