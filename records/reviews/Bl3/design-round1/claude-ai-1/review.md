所見
重大
S1. 数値の精度と計算の組み立てが正本に無い
（根拠: 正本の全体〔1／2 の 340〜1270 行〕に定めが無い／2／2 の 515 行・224 行・209 行）
段階 B と B-lens は bf16 で走っています（2／2 の 515 行）。transformers 4.57.3 の `Qwen3ForCausalLM` は、損失を計算しないときは出口の値を浮動小数に上げません。そのため、出口の値をそのまま使うと bf16 の刻みが入ります。たとえば値が 16〜32 の辺りなら、刻みは 0.125 です。
この計画の中にも前例があります。

* 同じ升目・同じプロンプトで、入力の長さが違うだけで主位置の残差が要素で最大 8 動いた記録があります（逸脱 D-BL3・2／2 の 224 行）。
* 手元で組み直した出口の値と、Colab の模型の出口の値の差は最大 0.0942 でした（209 行）。

効き目の大きさはまだ誰も知らないので、この揺れを前もって無視できるとは言えません。いちばん危ういのは、名前のある方向と帰無の方向を別の形のバッチで計算する場合です。揺れが方向の種類と揃うと、等方の外の札が偽って立ちえます。
直しの案:

* 加減そのものは段階 B と同じ bf16 のままにします（B が行動で試した介入と同じにするため）。そのうえで、最後の隠れ状態から出口の値と log-softmax までを float32 で計算すると正本に書きます。
* バッチの組み方を凍結します。升目と符号ごとに全ての方向を同じ形のバッチで流し、無操作は零のベクトルとして同じフックの道に入れます。方向の並びは凍結した種で混ぜ、名前のある方向を一か所に集めません。
* 下見に (vi) として「数値の揺れの床」を足します。方向は足さず、零のベクトルの無操作をバッチの別の位置・別の大きさで繰り返して、対数オッズの揺れの幅を記録します。許容と、超えたときの代わり（バッチの大きさを一にする、または全体を float32 にする）は下見の前に凍結します。これは D205（方向は一本も足さない）の中に収まります。
* 使った精度と揺れの床を、限界の文に置きます。

S2. 門と二つ目の札に、B-lens の芯の関数をそのままは使えない
（根拠: 第二部 §2〔1／2 の 86 行〕・正本 `gate.test`〔940 行〕／`gate_perm`〔2096〜2130 行、とくに 2113 行 `x = sg * V[...]`〕・`top_rank`〔2067 行〕）
`gate_perm` は、B-lens の物差しが方向について線形であることを前提にしています。押しを「行の符号 × 単位の家族ごとの値」で作る形です。
層三の押しはこれと合いません。

* 押しは升目と符号ごとに違います。
* 押しは、符号をかけた方向を加えて計算した値そのものです。奇関数である保証もありません。

素直に「家族」の欄へ升目と符号の鍵を入れ、符号の欄へ行の符号を入れると、減算の行と引く向きのランダムの行（-vrand・-vtd）で符号が二度かかります。`top_rank` も零を中心に |値| で比べるので、中心を等方の中央値に置く二つ目の札には使えません。草案が「B-lens の門と同じ並べ替え」「芯の関数を読み取りだけで呼ぶ」と書いていることが、この取り違えを招きます。
直しの案:

* 正本に、門の統計を次の形で書きます: 行 r の押し＝push[升目(r), 符号(r), π(単位(r))]。これ以上、符号はかけません。
* 芯の関数を二つに分けて並べます。
   * そのまま使うもの: `p_equal_tailed`・`holm`・`spearman`・`iso_directions`・`real_differences`。
   * 新しく書くもの: 非線形の押しの門、中心つきの二つ目の札。
* 合成データには、push(−u) ≠ −push(u) の場合と、帰無の中心が零でない場合を必ず入れます。線形の合成データでは、この符号の誤りは隠れます。

M3. 読みの表の書くことに、言い過ぎが三つある
（根拠: 正本 `reading_rules`〔1／2 の 973〜1003 行〕・第二部 §9）

M7. 層ごとの差分の定義と器の約束
（根拠: 第二部 §8・正本 `descriptive.layerwise`〔1／2 の 947〜956 行〕・禁止語〔1071 行〕／`direct_path`〔2249〜2263 行〕）

* 定義の曖昧さ: 「残差の差を最終の正規化と語彙の行列に当てた」は二通りに読めます。RMSNorm は非線形なので、各層で「正規化(h＋Δ) の出口の値 − 正規化(h) の出口の値」と定めます。B-lens の `direct_path` の before／after と同じ形です。
* 最後の層の二重の正規化: transformers 4.57.3 の `check_model_inputs(tie_last_hidden_states=True)` は、`hidden_states` の最後の要素を、最終の正規化の後の値で上書きします。そこに最終の正規化をもう一度当てると二重にかかります。
   * 層の出力はデコーダ層のフックで取るか、最後の層を別に扱うと定めます。
   * 「最後の層の行は、実際の読み取りの効き目と許容の内で一致する」ことを、器の自己検査に入れます。
* 表の大きさ: 升目と符号を全て並べると、18 層 × 7 方向 × 13 組 × 3 値で、およそ 4900 個になります。D208 の「少なく絞る」に合わせて先に絞ります。
* 禁止語との衝突: 注「転換層の読みは付けない」（955 行）は、正本が足した禁止語「転換層」（1071 行）に当たります。言い換えるか、許す文の一覧を置きます。

軽
L1. 帰無の本数と解像度
999 本では、Holm の第一〜四段を通るのは、999 本すべての外にある行だけです。近道が使えれば 9999 本でも順伝播は安く済みます。ただし npz は float64 でおよそ 205 MB になります（float32 で保つか、リポジトリの外に置いて SHA だけを記録に置く）。999 本のままにするなら、この解像度を限界の文に書きます。
L2. 読み取りの文字の外への漏れ
本の計算でも、方向ごとに「選択の文字と refuse の頭の確率の和」を記録し、`mass_min` を下回った方向の数を記述に並べます。対数オッズは文字の中の比なので、確率が文字の外へ逃げても値は動かず、そのままでは見えません。
L3. q7 と、零に近い行動の変化の符号
（根拠: 正本 1151 行／2／2 の 432 行・591 行〜）
B の v̂ の腕と無操作の差には、零に近い行があります（sub:N1 は −2.0 pt）。B-lens の p8 は、零に近い値の符号で答えが決まりました。区間が零を含む行は「該当なし」とするなど、扱いを先に決めておきます。
L4. 下見の記録を報告に常に並べる
今は〈下見で止めた〉ときだけ下見の記録を並べる形です。続けたときも、(iii) の較正と (iv) の印を、主の行の札の隣に並べる決まりにします。
L5. 門の行動の量の感度（任意）
量が零の (a) による食い違いは 13 行・29 試行です。主の量は破局のままにして、選択 (a) の対数オッズでの門を記述として一つ並べると、食い違いの効き方が見えます。
L6. 門の押しを中心化しない理由の書き方
（根拠: 正本 939 行）
方向を単位にした入れ替えは、行の升目と符号を保ちます。そのため、升目と符号の中で方向に共通の動きは、観測にも入れ替えにも同じように入ります。中心化の有無は検定の妥当性を変えず、変わるのは検出力だけです。今の理由の文（「行動の側に引く値が無いので」）より、こちらが本当の理由なので、差し替えを勧めます。

   * 様式が段階 B で加減に動いた道であり、甲はそれを閉じること。
