## 所見

### 重大

**R1　読み取りの位置の a は、指示の雛形で `{"choice": "` の直後にある文字でもある**
（根拠：第四部 4-2 の JSON の指示・4-4 のプロンプトの末尾・転記行 A・§4 (iv)）

- 雛形と書き出しが重なっている。
  - JSON の指示は、両方の族で `` ```json⏎{"choice": "a"|"b"|… `` と書く。
  - 甲の書き出しは、この雛形の頭と同じ文字列である。雛形ではその次が a である。
  - つまり破局の文字と、雛形で最初に並ぶ値が、同じ a になっている。
- refuse の頭の「ref」にも手がかりがある。プロンプトの末尾の近く（4-4 の末尾 40 トークン）で、「 "」の直後に来る。「 "」は書き出しの最後と同じ字面のトークンである。
- そのため甲の a の対数オッズには、選択の構えのほかに、プロンプトの中の同じ並びの続きを写す働きが入りうる。
  - どれだけ入るかは誰も知らない。今の設計では分けられない。
  - 揺れの版 V1・V2 はどちらも `"choice": "` を保つので、(iv) はこの重なりを揺らさない。
- 札はこの読み取りの位置の記述なので、札の正しさは崩れない。崩れうるのは、§0・§9 の「破局の文字の対数オッズ」を選択の構えとして読む前提である。
- 提案（草案2）：
  - (a) §3.4・§10・「答えられないこと」に一行ずつ足す。
  - (b) 器 bl3_facts.py が升目ごとに転記行 B へ印字する。印字するのは、書き出しのトークン列がプロンプトの中に現れるか、現れるならその次のトークンは何か、である。
  - (c) 任意：(iv) に、雛形との一致を崩す版を記述として足す。例えば鍵の後の空白を変え、選択の文字が一つのトークンに割れることを器が確かめたもの。止める条件にはしない。

**R2　B-lens の芯の関数のうち、門の並べ替えと最上位の判定は線形を前提にした口になっている**
（根拠：第四部 blens_core.py の `gate_perm`・`top_rank`、草案 §2・§5・§7）

- `gate_perm` は押しを「符号 × V[単位, 家族]」で作る。
  - B-lens では、物差しが方向について線形で、家族の中で升目に依らなかったので、これで足りた。
  - 層三の押しは升目と符号ごとの値である。−u の効き目は −(u の効き目) にならない。
- 本文は「B-lens の門と同じ並べ替え」「芯の関数を読み取りだけで呼ぶ」とだけ書き、呼び方を決めていない。B-lens の呼び方のままだと、二つの誤りが起きうる。
  - 行の符号 −1 を渡すと、減算の行（static・td・rand の減算の行）で符号が二重に掛かり、押しが反転する。
  - 家族を渡すと、升目の違いが消える。
- 正しく呼ぶ形はある。
  - 家族の鍵を「升目|符号」にし、行の符号はすべて +1 にする。
  - V[u][升目|符号] には「符号つきの方向 u を、その升目で加えた効き目」を置く。
  - 十三の組と七本の方向はすべて計算するので、値は揃う。
- `top_rank` は零を中心にする。二つ目の札では、行と比べる相手の値から等方の中央値を引いてから渡す必要がある。
- これは段階 B の逸脱（一）と同じ「器と器の食い違い」の型である。合成データが線形で対称なら、通ってしまう。
- 提案（草案2）：
  - 正本の `gate` と `labels.second` に、呼び方を機械で読める形で書く。
  - 合成データに、このずれを植える（Q10 の答えの並び）。

### 中

**R3　数値の精度と、加減を足す置き場が正本に無い**
（根拠：正本の `inputs`・`readout`・`independent_recompute`、第六部の頭の「bf16」、第五部 §3 の手元の logits の突き合わせ・最大の差 0.0942）

- bf16 の刻みが効き目に乗る。
  - 段階 B は bf16 で走った。transformers 4.57 の Qwen3 は、私の記憶では出口の logits を上の精度に上げずに返す（確かめていない）。
  - bf16 の刻みは、|z| が 8〜16 で 0.0625、16〜32 で 0.125 である。
  - 効き目は二つの順伝播の差なので、この刻みが乗る。その刻みが、999 本の帰無の中の同値と、下見の (v)（許容 0.05）に入る。
  - 効き目の大きさは誰も見ていない。刻みが足りるかは先に分からないので、先に固定する。
- 精度を安く保つ方法がある。
  - 量は、読み取りの集合の logits だけで決まる（z_a − logsumexp(z_他)。全語彙の正規化は打ち消し合う）。
  - 順伝播は段階 B と同じ bf16 のままにする。最後の残差を fp32 に上げ、最後の正規化と語彙の五つの行だけを fp32（か fp64）で当てればよい。
  - 全語彙の softmax が要るのは、(i) の質量だけである。
- 加減の置き場を書く。
  - 置き場は層 17 の出力（`hidden_states` の 18）である。加える前の型と、係数を掛ける所も書く。
  - これらは段階 B の凍結の関数を読み取りだけで呼ぶ、と書く。§2 の呼ぶ関数の並びには、加減の関数が無い。
- 独立の再計算にも抜けがある。許容と、食い違ったときの扱い（止めるか・どちらを採るか・逸脱に記帳するか）が無い。

**R4　甲は様式の選びの経路を落とす。段階 B には、その経路が大きかった行がある**
（根拠：第六部 §4「様式の差 61.0 pt」「判定保留（様式転位）」・S4 の反証の区画、転記行 A）

- 甲は両方の腕に直答の書き出しを置く。そのため、方向が「推論するか直答するか」の選びを変える分は見えない。
- 段階 B では、その経路が大きかった行がある。
  - 主の行 cross:S4:O-Ncold+vNk は、JSON 直答が 80.0／19.0 で「判定保留（様式転位）」だった。
  - 門の行の S4|Osec-Ncold+v6b と rand:0 は、全試行が直答の c だった。
  - 直答の出力は 725 件すべて c で、様式と選択が一緒に動いている。
- これらの行では、段階 B の行動の変化の一部が、甲の測らない経路を通っている。門の順位にも入る。
- 提案（草案2）：
  - (a) 限界と「答えられないこと」に一行ずつ足す。書くのは、様式の選びの経路と、加減された推論の文を通る経路。
  - (b) 段階 B の札の注（様式転位・ランダム方向の不均一）を、主の表と門の行に写す。
  - (c) B-lens の「崩れの行を除いた門」に当たる記述を一つ、札なしで置く。行の決め方は、段階 B の記録だけで決まる形で先に決める。

**R5　二つ目の札の偶然の目安 0.3087 は、効き目がほぼ奇のとき低く出る**
（根拠：正本 `chance_second`、§5・§10・§15）

- 0.3087＝8/49＋8/55 は、向きまで数えた 48 本（54 本）を、別々の相手として数えている。
- 中心を引いた後に効き目がほぼ奇なら、±d はほぼ同じ |値| を持つ。実質の相手は 24 本（27 本）になり、目安は 8/25＋8/28＝0.6057 になる。
- 合成の数で確かめた（模型は使わない）。対の値を「奇の部分＋奇でない部分×ε」で作った。
  - 一行が最上位になる割合は、ε＝0 で 0.0405（1/25）だった。
  - ε が大きくなると 0.020（1/49）に近づいた。
- §15 は「向きを数えることは二つ目の札を付きにくくする」と書く。
  - 実際には、ほぼ線形のときにはほとんど当たらない。一方で、印字する目安は半分になる。
  - これは、直しの中に入る起草者の側への傾きの型（札を珍しく見せる向き）にあたる。
- 提案：
  - 目安を幅（0.309〜0.606）で印字する。
  - 順位を「向きつき」と「対の単位」の両方で印字する（記述）。
  - §15 の文を直す。
  - §10 の「和の上限」を言い直す。和は、付く数の期待としては正確な値で、「一つ以上付く割合」の上限である。

**R7　二つ目の札の中心を、等方の中央値に置く理由が足りない**（§5・§16）

- 比べる相手は実在の差である。一方、等方の帰無は、偏った残差の中では低い棒である（本文自身の限界の文）。
- 実在の差が、等方と違う共通の動きを持つとする。そのとき中心からの |差| で最上位を決めると、実質その向きへの片側の極値になる。
- 提案：理由を一段足す。記述として、行ごとに比べる相手の中央値も並べる（札の判定は変えない）。

**R10　読みの規則の抜けと言い過ぎ**（§9・正本 `side_rule`・q7）

## 伺いたいことへの答え

1. **問い**：一つに絞れている。「この読み取りの位置の記述」としてなら、この材料で答えられる。
   - 「答えられないこと」に足すもの：R4 の二つの経路、R1 の写しとの区別、(a) の量。
   - あわせて R19。
2. **甲**：三つの事実は、次のように読める。
