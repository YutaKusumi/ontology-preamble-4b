### 凍結の前に直すもの

**所見 1（中くらい・確実に起きる）: 凍結の本文の器が、正しい流れで必ず止まる。本文には一時の置き場の道筋が入る**
- **置き場**: `tools/make_frozen_Bl3.py` の `build_frozen`（凍結の一行を代わりの行に替え、一時の置き場の `frozen-standin.src.md` から組む）と、`rebuild_and_check` の `frozen_src_rebuilt_same`。原因は `tools/build_draft_Bl3.py:71` で、組み立ての記録の行に「原稿の道筋と SHA16」を書くことです。
- **起きること**:
  - 本文の組み立ての記録に `原稿 ../tmpXXXX/frozen-standin.src.md SHA16 <代わりの原稿の値>` が入ります。一時の道筋が凍結物に残り、原稿の SHA16 も実の FROZEN.src.md と違う値になります。
  - 組み直すたびに一時の置き場の名が変わるので、照らしは必ず「違う」になります。凍結の器 `prepilot_checks` も同じ関数を呼ぶので（`freeze_Bl3.py:162`）、下見の前の凍結は通りません。
- **確かめ方**:
  - 手元の写しで、同じ原稿を `build_frozen` で二度組んで比べました。差は上の一行だけでした。
  - 作業木の写しで `make_frozen_Bl3.py --words … --commit … --date …` を端から端まで走らせると、「凍結の本文の確かめが外れた: ['凍結版の原稿を組み直した本文が、凍結の本文と違う']」で止まりました。本文の 161 行に一時の道筋が入っていました。
- **なぜ捕まらなかったか**: 自己検査は `build_frozen` だけを見ていて、`rebuild_and_check(fsrc, fout)` は走らせません。正式の記録の凍結の器の走り（check-only）では、凍結の本文がまだ無いので、この枝は通りません。
- **直し方**:
  - 組んだ後に、代わりの原稿の道筋と SHA16 を `rel(src_path)` と `sha16f(src_path)` に置き換えます（ちょうど一度だけ当たることを assert します）。
  - 「main と同じ手順で組み、`rebuild_and_check` が同じと答える」自己検査を足します。

**所見 2（中くらい）: 判定の段の後に裁定 D234 の台帳に記すと、結果を開く段が止まる**
- **置き場**: `analyze_Bl3.py` の `judge` が `freeze_record_sha16 = sha16f(FR_PATH)`（ファイル全体）を置き、`open_checked` が今のファイル全体と照らします。

  - 台帳は凍結の記録の `deviations` です（`build_report` がそこから読みます）。判定の後・開く前に記すと、「凍結の記録が一致だけを見る段の後に変わった（開かない）」で止まります。
- **確かめ方**: `open_checked` に合成の記録を与えて試しました。判定の記録を置いた後に `deviations` を一行足すと、この文で止まりました。

- **直し方**:
  - 判定の段で、凍結の記録のうち `deviations` を除いた部分の SHA16 と、台帳の行の数を置きます。
  - 開く段では、除いた部分が同じで、前の台帳が今の台帳の頭と同じことを照らします。
  - 報告の組み立ても同じ錨を使います（所見 3）。

**所見 3（中くらい）: 報告の組み立ては、読む集計が「照らした開く段の出力」であることを確かめない。DRY の集計も通る**

## 5. 確かめて問題なしとしたもの

- **判定・開く・報告の三つの段が照らす十のファイル**: すべて凍結の記録の鍵に入ります。`import_closure(TOOLS)` と `frozen_files(T3)` を手元で計算し、`FROZEN_CHECK` の欠けは 0 でした。
- **起動器の「疎な取り出しの内側で無ければ外れ」**: 凍結物のうち疎な取り出しの内側で今のコミットに無いのは、凍結で作るもの（凍結の本文・原稿・数の検査の記録・書式）と、push する方向の記録だけでした。正しい流れでは止まりません。外側（`results/dirB/…`）は飛ばされます。
- **予想の SHA-256 が生のバイトで取られること**: `.gitattributes` が `* text=auto eol=lf` なので、取り出しの環境によって変わりません。
- **正本 `decisions` の鍵**: 53 個すべて `D` と数字だけです。数での比べは安全で、D58〜D90 は外れます。
- **本の凍結の封印の錨**: 封印を足したコミットの凍結の記録と照らす形です。試みのコミットは、凍結物の表と npz で照らします。どちらも台帳の追記で止まらないことを、行で確かめました。
- **Stop の型と、`__main__` の except の順**: `SystemExit`→`Stop`→`Exception` の順で、正しく並んでいます。
- **組ごとの zip**: `od` の外に置かれるので、入れ子になりません。
- **相 check の升目の鍵**: 手元の組み立ての鍵（9 升目・門の行だけの升目 S4|Osec-Ncold）と揃っています。
- **開く段の組み直しの一致の照らし**: データが不一致のとき、書き換えた `agree` を捕まえます。
