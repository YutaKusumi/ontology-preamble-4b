## 2. 新しい所見

### 凍結の前に直すもの

**新-1（中）: 起動器が書いた組の SHA-256 を誰も照らさない**
- 何が: boot 510 は「一致だけを見る段が読む組の出力の同定」と注して `session['part_sha256']` を書きます。しかし analyze は一度も読みません。
- なぜ問題か: judge が記録する SHA は手元のファイルから取った値で、open もその同じファイルから取り直します。照らす相手が同じものから作られていて、Colab から手元までの間の変わりを捕まえません。dry_run 837-840 も鍵があるかだけを見ます。
- 確かめ方: grep で読み手が boot と dry_run の鍵の確かめだけであることを見ました。
- 直し方: `load_outputs` で、組の JSON の SHA-256 が session の `part_sha256` と同じことを求めます。DRY でも同じにします。合成データに、組を書き換えて session はそのままの写しで judge が止まる確かめを足します。

**新-2（中）: 封印の照らしが、結果の後は手元のファイルの間だけで閉じている**
- 何が（一つ目）: judge は `sealing_record_sha16` を記録します（analyze 394-395）。しかし open_checked（453-479）は照らしません。build_report の load_inputs（338-367）も、judge の記録を読みません。
- 何が（二つ目）: 報告の時の鎖は「予想 → 封印の記録 → FR.main_freeze.seal」で、三つとも手元の作業木にあります。open の後に三つをそろえて書き換えると、報告は通ります。
- 外の錨は既にある: 本の凍結は下見の試みのコミットの封印の記録を照らしており（freeze 338-340）、そのコミットは `main_freeze.sessions[].commit` に残っています。
- 直し方: open で封印の SHA16 を judge の記録と照らします。報告の頭で、封印の記録を `git show <下見の試みのコミット>:records/Bl3/sealing-record-Bl3.json` と照らします。凍結の記録の全体の SHA を報告の時に求めると、台帳を足す正しい流れで止まるので、変わらないもの（封印の記録と main_freeze の部分）だけを照らすのがよいと考えます。

**新-3（中）: 手元の本の凍結を、相 main が使った下見の記録に結ばない**
- 何が: judge と open は、手元の `FR.main_freeze.pilot` の外した升目と揺れの床を使います（analyze 262, 418）。しかし、session の commit にある凍結の記録の main_freeze と照らしません。起動器が書いた `pilot_used`（boot 469-472）とも、main.json の `dropped`・`batch`（bl3_run 479）とも照らしません。
- なぜ問題か: 手元で外した升目が一つ多いと、行が黙って減り、Holm の段の数が変わります。逆に一つ少ないと、升目が無くて落ちます。
- 直し方: judge で、`git show <session.commit>:records/Bl3/FREEZE-RECORD-Bl3.json` の main_freeze が手元と同じことを見ます。あわせて、main.json の外した升目とバッチを下見の記録と照らします。

**新-4（軽）: 照らす器の一覧が手書きで、閉包から漏れがある**
- 何が: `FROZEN_CHECK`（analyze 311-312）に、report_lint が import する `tools/numbers_lint.py`・`tools/runs_A.py` がありません。open が読む次の入力もありません。
  - `records/B/analysis-B-2026-09-22.json`
  - `results/stageB/*/trials-*.jsonl`（門の行動の量）
  - `results/Blens/calib-Blens.json`
  - `records/Blens/design-facts-Blens.json`
- 直し方: 一覧を `freeze_Bl3.import_closure` と読む入力から組むか、足します。

**新-5（中・問い 4）: DRY でない枝が、正式の記録で一度も走っていない**
- 走っていない枝:
  - judge の DRY でない枝（等方の本数・凍結の記録・`frozen_versions_bad`）
  - open の `freeze_record_sha16` の照らし
  - 台帳で許す差分の道
  - 起動器の相 pilot と main の封印と凍結の照らし（DRY は `dry_no_gate`）
  - 報告の器の CLI（`load_inputs`）
- なぜ問題か: 72 のうち 72 はこれらを覆いません。多くは止まる側に倒れますが、最初に走るのが本物の出力の上になります。
- 直し方: 合成の組（等方は正本の本数で、純粋な関数の段で足ります）と、一時の git の置き場に置いた凍結の記録と封印の記録で、これらの枝の「通る」と「止まる」を確かめに足します。

**新-8（軽）: DRY の CLI が本物の置き場に書き、報告が DRY の集計を黙って受ける**
- 何が: DRY で `--out` を与えないと、judge と open は本物の置き場（`records/Bl3/judge-Bl3.json`・`analysis-Bl3.json`）に書きます（analyze 516-518, 537）。build_report は `A['dry']` を拒まず、報告に DRY と書きません。sweep 78 も DRY なら本数を緩めます。
- 直し方: DRY では `--out` を必須にし、報告の器で DRY の集計を拒みます。

### 記録に置けば足りるもの

- **新-6（軽・器の決め）**: 相 pilot は台帳を見ずに `FR['frozen_sha16']` と照らします（boot 174）。そのため、器を直した後の下見のやり直しは起動器で止まります。本の凍結は台帳の差分を許し、今回やり直しの記帳を求めるようにしたので、食い違います。検分の版からある振る舞いです。加えて `ledgered[path]` は最後の一件しか持たないので、同じファイルを二度直すと正しい流れでも止まります（freeze 311-320）。
