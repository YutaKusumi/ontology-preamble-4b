# B-lens 層三の器についての意見（claude.ai）

**系統と機種**: 起草者と同じ Claude 系です。機種も同じ Claude Opus 5.5（claude.ai の個体）です。claude.ai の票は、何票あっても同一系列の一票として数えてください（裁定 D59）。

- 本物の模型では何も計算していません。本物の重み・方向・段階 B の記録も読んでいません。
- 結果の見込みは書いていません。下に出てくる割合は、乱数の数の上で器の決まりがどうふるまうかを示すものです。本物の値の見込みではありません。
- 確かめに使った台本は、下に付けた `opinion_checks_Bl3.py` です（numpy だけで動きます）。

## 0. まとめ

新しい点は、重いものが二つ（A1・A2）、中くらいが三つ（A3〜A5）、軽いものが十あまり（B1〜B10）です。

二つの道が同じ向きに正本から外れている所は、読んだ範囲では見つけられませんでした（§1 に、何を見てそう判断したかを書きます）。重い二つは、どちらも二つの道の外にあります。集計の器と、独立の再計算の一致の決まりです。

## 1. 二つの道が共有しうる読み違い

### 1.1 器を見る前の、正本の私の読み

1. **入力**: `apply_chat`（生成の頭つき）のトークン列の後ろに、転記行 A の 7 トークンを id のままつなぐ。主位置はプロンプトの最後、読み取りの位置は列の最後。
2. **帯**: 主位置から読み取りの位置まで、両端を含む。段階 B では、書き出しの各トークンも加減の下で入力されたからです。
3. **算術**: v（‖v̂‖＝転記行 D の 1.30123 にそろえ済み、係数は入っていない）を層の出力の型に直し、sign×coef を一度だけ掛けて、bf16 のまま足す。coef＝2.0 と ±1 は bf16 で正確なので、型を直す順と掛ける順は値を変えない。
4. **層**: `layers[17]` の出力。これは `hidden_states[18]` にあたる。
5. **読み取り**: 最終の正規化の入力（層 35 の出力）を float32 に上げ、RMSNorm（g は float32）を当て、集合の行（a・b・c（・d）・ref）を float32 で掛けて、z_a − lse（残り）を取る。`hidden_states[-1]` は正規化の後の値なので使わない。
6. **無操作と効き目**: 無操作は零のベクトルを同じ道に流したもの。効き目は、同じ升目と符号の無操作との差。
7. **減算の行と比べる相手**: 減算の行は static に −1 を掛ける。等方の帰無も同じ升目と符号で流す（−1 を掛けた等方）。比べる相手は同じ升目の ±1 の両方の向きで、どちらの行の符号でも同じ集まりになる（除く対だけが違う）。

### 1.2 二つの道との照合（問題なしと見た所）

七点とも、二つの道は私の読みと一致しました。見た場所は次のとおりです。

- **入力**: `bl3_run.build_cells`（330–350）と、書き換えの道の `cell_input`（129–185）。
- **帯**: 段階 B の `make_hook` の prefill の枝（184）に、起点 mp を渡す形と、近道のときに mp から始まる塊へ起点 0 を渡す形（`bl3_run` 114–123）。書き換えの道は 239–240。
- **算術**: `make_hook` の 178 と、書き換えの道の 239。どちらも float32 → bf16 → sign×coef の順。
- **層**: `register_hook` から `decoder_layers()[17]` へ掛ける所と、書き換えの道の 231–235。起動器の 270–272 と、書き換えの道の `check_layer_and_coef` が正本の添字と照らしている。
- **読み取り**: `bl3_run` の 78–93 と、125（正規化の前の hook）。書き換えの道は 254–268。量は `bl3_core.log_odds_a`（37–40）。集合の順は `bl3_run` の 344 と、書き換えの道の 173–181。
- **無操作**: `bl3_run` の 72–73 と 320、書き換えの道の 317 と 331。
- **符号と比べる相手**: `bl3_core.recompute_set` の 261、`analyze_Bl3.row_labels` の 79–87 と `override` の 158–161、`cell_sign_sets` の 247–249。

### A5（中くらい・新しい点）二つの道が同じ所から受け取っていて、独立でない入力

二つの道が独立しているのは、加減の仕組み・層の回し方・読み取りの実装の三つだけです。次の四つは共有されています。

- (a) 転記行 A・B（`bl3_facts`）
- (b) 方向の npz と、それを読み込む `BR.load_dirs`。名と配列を結ぶのはこの関数で、起動器の 251 と 436 で `dirs` をそのまま書き換えの道に渡しています。
- (c) どの方向をどの符号で流すか。これは `recompute_set` が作った `dbr` で、書き換えの道は自分では導いていません（起動器の 414–436）。
- (d) 札を出す関数（`row_labels`・`labels_signature`）。一段目も二段目も同じ関数を通ります。

(c) と (d) は正本と照らし、A2 を除いて合っていました。(a) と (b) は、作った器が束に無いので確かめていません。

直し方の案（どれも安く足せます）:

- 書き換えの道か相 check で、正本の `independent_recompute.what` と `nulls.real.rule` から（方向・符号）の組を自分で作り、渡された `dbr` と一致することを assert する。
- Bl3 の npz の static・loaded・Nk・td が、段階 B の凍結の npz の `*__0.5` とバイトで同じで、‖static‖ が 1.30123 であることを確かめる。`bl3_directions --check` が既にそうしているなら、その確かめを凍結した確かめの一覧に入れれば足ります。

独立の範囲の一般論は、記録にある点です（開発の記録 §7.7・T8）。書き出しの id が生成した id と違いうることも、記録にある点です（正本 `limits`・P693）。

## 2. 独立の道の無い所

### A1（重い・新しい点）下見で升目を外すと、集計の器が落ちる

- **根拠**: `run_main_phase` は外した升目を流しません（`bl3_run` 461–462）。ところが集計の器は、外した升目の効き目を読みに行きます。
  - `analyze_Bl3.gates` の 109 は、門の行すべての升目と符号について `ue` を作る。
  - `recompute_agreement` の `main_ov`（167–172）は `dropped_cells` で行を除いていない。
- **起きること**: どちらも KeyError で落ちます。落ちるのは結果を開く前の「一致だけを見る段」で、この落ち方は器の誤りでも不一致でもありません。q1 の「一部の升目を外して続ける」の枝は、今の器では最後まで通りません。凍結の後に直すと逸脱になります。
- **確かめ方**: 付けた台本の「一」を走らせてください。gates と recompute_agreement が `KeyError 'S1|Onull|+1'` で落ちます。
- **直し方の案**: 二行で直ります。`gates` の頭で外した升目の行を除く行を足すことと、`main_ov` の条件に外した升目を足すことです。直した写しで、合成の完全な入力について gates が通り、recompute_agreement の一段目・二段目がともに一致になることを確かめました（本の器は元に戻してあります）。
- 合成データの器は外れる升目を芯の関数（`K.gate`）でしか試しておらず、試しの六度目では `dropped: []` でした。そのため見えなかったのだと思います。

### A2（重い・新しい点）札の一致の「割合を決めた裾」を、全ての行で比べている

- **根拠**: `labels_signature`（100–102）は、全ての行の `tail` を比べます。正本 `independent_recompute.agreement` の「割合を決めた裾（上か下か）」には、行の限りが書いてありません。同じ文で「効き目の側」は「等方の外の行の」と限られています。
- **なぜ問題か**: 帰無の内側にある行（p がほぼ 1）では、裾は「値が帰無の中央値の上か下か」だけで決まり、札には何も効きません。それなのに、許容の内の小さな揺れで反転し、不一致として止まります（D219）。
- **確かめ方**: 付けた台本の「二」です。v̂ の 8 行だけに揺れを入れ、等方は 1999 本、行も帰無も同じ分布から引きました。一致が落ちる割合は次のとおりです。

| 揺れ／帰無の広がり | 今の決まり | 裾を等方の外の行だけで比べた場合 |
|---|---|---|
| 0.005 | 0.003 | 0.003 |
| 0.02 | 0.060 | 0.010 |
| 0.05 | 0.157 | 0.043 |

  食い違いの大半は `tail` の欄でした。本物の計算で揺れ／広がりがどれだけになるかは、走らせる前には分かりません。
- **直し方の案**: 凍結の前に、「割合を決めた裾」を等方の外の行に限る登録者の裁定をいただくことを勧めます。正本の文が変わるので、凍結の後には直せません。
- Holm の境で判定が変わる仕組みそのものは、記録にある点です（合成の形の「Holm の境で一本違う p」）。内側の行の裾は新しい点です。合成の器は 2 行と等方 49 本でしか比べていない（`rows_subset`・dry の 323）ので、この性質は出てきません。

### A3（中くらい・新しい点）升目を外した後に、偶然の目安を数え直していない

- **根拠**: `analyze` の 244 は、正本の 0.3087 と 0.6057 をそのまま写しています。正本 `pilot.decision.drop_effects` は、残った行で数え直すことを求めています。
- **確かめ方**: この二つの値は、行ごとの 1/(比べる相手の数＋1) の和で再現できました（8/49＋8/55 と 8/25＋8/28）。S1|Onull を外すと 0.2701 と 0.5300 になります。
- **直し方の案**: 残った行で計算する。組み立ての器（束に無い）が既に数え直しているなら、記録に置けば足ります。

### A4（中くらい・新しい点）下見の分かれ道を、端から端まで通していない

- **根拠**: 合成の器の試しの六度目も、起動器の DRY も、「続ける・バッチ 16・近道あり」の枝しか通っていません。A1 は、まさにこの穴に隠れていた誤りです。
- **直し方の案**: 合成の器に、作った下見の記録を三つ足し、`run_main_phase` → judge → open まで通すことを勧めます。
  - 主の升目を一つと門の行だけの升目を一つ外した記録
  - バッチ一の記録
  - 近道なしの記録

### 問題なしと見た所

- **近道**: `prefix_cache`・`_expand`・`forward`（96–123）。元は `ids[:mp]` で、塊は mp から、起点は 0。位置は cache の長さから決まります。使い回した cache のテンソルは書き換えられません（更新はつなぎ合わせで行われるため）。
- **バッチ**: `batch_plan`（266–276）と `run_cell_sign`（255–292）。埋めた分を飛ばし、無操作は一つで、効き目は同じ升目と符号の無操作から取っています。`cell_sign_sets` の数（12×2034、7、112）は転記行 E と一致します。
- **下見**: `run_pilot`（170–234）は `pilot.order` の順どおりでした。(vi)(b) で止めたときは早く返り、無操作はバッチの最初の位置の値を使い、(v) は全ての升目に掛かっています。`vi_decision`・`cache_tol`・`cells_decision` の値は、自己検査を走らせて確かめました。
- **札**: 等しい裾の割合、Holm（段を下回る・外した後の段の数）、効き目の側、二つ目の札の中心と二つの順位、等方の最上位の割合、除く対（24 と 27）。
- **門**: 符号を +1 にして、家族の鍵を「升目|符号」にし、押しを `eff[fam][π(単位)]` から取っています。行の無くなった単位を除く扱いと、記述の門三つも正本どおりです（A1 を除く）。
- **乙**: 門の行の符号ごとに、無操作と同じバッチで流しています。

## 3. 合成データの確かめの盲点

合成の確かめをすべて通っても、本物の模型の上で結果を変えうる誤りとして、次の形が残ります。

1. **二つの道と合成の器が同じ入力を使う誤り**: 転記行、npz の名と中身、等方と実在の差の作り方（A5）。合成の方向は乱数なので、ここには届きません。
2. **規模に依る誤り**: 正本の相対の加減の大きさで試したのは、書き換えの道の変種だけです（記録にある点：開発の記録 §5.1 と §7.6、器の段の記録 §7）。本の道の近道とバッチ、二段目の比べは、飽和する大きさでしか通っていません。近道の assert はありますが、同じ大きさで二段目の比べも記述として測ることを勧めます。
3. **分かれ道**: A4 のとおりです。
4. **一致の決まりの数の上の性質**: A2 のとおりです。
5. **読み取りの集合の中身**: 小さな模型では、`calibrate_readout_rows` が渡された id をそのまま強く出す形に置くので、id を取り違えても合成は通ります。本物の模型では、取り違えは下見の (i) の「測れなかった」として出てきます。これは採点される q1 の結果であって、器の誤りとしては出ません。転記行 A（次のトークンの数え上げ）が守りになっています。
6. **最後の層の自己検査**: 実装では、層 35 の hook の出力と、正規化の前の hook の入力が同じテンソルです。そのため、いつでも通ります。この検査が確かめているのは「`hidden_states` を使っていない」ことだけです（B1）。

## 4. 凍結の前に直すものと、記録で足りるもの

**凍結の前に直すもの**: A1・A2（裁定が要ります）・A3・A4・A5（安い錨を足す）です。

加えて、書き換えの道の `--dry` は、`bl3_run` の SHA16 7ECB9CF764F4F8AE を相手に走らせた記録です。束の `bl3_run` は CB38D8EB2EC9A448 です。凍結する版どうしで走らせ直し、その SHA を記録してください（軽い）。

**記録（限界・報告の注）に置けば足りるもの**（すべて軽い）:

- B1: 最後の層の自己検査は恒等で、検出力を持たない。
- B2: 近道の assert は `pc['end']` の記録を見ていて、cache の実の長さを見ていない（`bl3_run` 119）。
- B3: `K.gate` は単位が一つ残ったときも「判定不能」にする（146）。正本は、行が残らないときだけ判定不能とする。
- B4: 層ごとの余弦に符号の付かない方向を使っている（280）。−1 の行では符号が逆に出る。
- B5: (iii) の変換を通した値は、全語彙の中での確率（211）。集合の中の値ではない。
- B6: 全語彙の softmax は 151,936 行で、トークナイザの外の 267 行を含む。
- B7: 二段目の許容は 17 個の値の幅から作るのに、当てるのは約一万六千の差の最大。GPU の揺れの裾が長いと、許容を超えて止まりうる。
- B8: `glob(...)[0]`（analyze 65・bl3_run 393–394）は、ファイルがちょうど一つであることを assert するとよい。
- B9: 起動器は `main_freeze.pilot`（390）を、集計の器は `pilot_attempts[-1]`（365）を読む。二つが同じであることを確かめるとよい。
- B10: 外した升目の乙の扱いが、正本に無い。
- 四分位の取り方（numpy の線形補間）が、正本で決まっていない。
