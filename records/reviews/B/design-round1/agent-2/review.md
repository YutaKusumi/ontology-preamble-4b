**判定: 差し戻し。** 理由は重大 5 件のうち少なくとも三つが、設計の中身ではなく「草案・転記行に書いてある数や配線が、正本の定義・生成器の実際の振る舞いと合っていない」型の食い違いで、そのうち一つ（重大1）は機械生成の転記行が七つの数を取り違えたまま印字している事実だからである。重大2 は、依頼文 §1 の重点 2 そのもの（選定の雑音）の数が、正本に書かれた選定規則ではなく別の規則の数であることを示す。重大3〜5 は重点 3（統制の配線の向き）に当たる。いずれも設計の作り直しではなく、正本と転記行の直しで閉じられる範囲だと見る。

## 2. 重大

### 重大1. 転記行 B の七つの数が、生成器の引数のずれで全部ずれたラベルに印字されている

**(a) 対象**: `records/B/design-facts-B.md` の転記行 B ／ `design/design-stageB-draft6.md` §6 の転記行 B ／ `tools/design_facts_B.py` の `F['B']`（92〜96 行）。

**(b) 事実**。印字されている逐語:

> 対比: 確証 16（…）・**記述 0**（無操作との差 **17**・O 減算 **8**・実在する腕対の差方向 **4**・S4 の反証 **4**）・ランダム方向 **1** 本（層ごとにノルム一致・合併して一腕）・**id 重複 3**。

正本 `design/contrasts-B.json` から自分で数え直した値（`descriptive_families` の各キーの `contrasts` の長さ、`random_control.count`、全 33 個の対比 id の重複数）:

| 欄 | 印字 | 正本から数えた値 |
|---|---|---|
| 記述（合計） | 0 | **17** |
| 無操作との差（`B_desc_vs_noop`） | 17 | **8** |
| O 減算（`B_desc_O_sub`） | 8 | **4** |
| 実在する腕対の差方向（`B_desc_textdiff`） | 4 | 4（偶然一致） |
| S4 の反証（`B_desc_S4`） | 4 | **1** |
| ランダム方向 | 1 本 | **3 本** |
| id 重複 | 3 | **0** |

原因は生成器の書式欄と引数の対応である。`F['B']` の書式欄は「記述 %d（… %d・%d・%d・%d）・ランダム方向 %d 本・… id 重複 %d」の順だが、引数は `(…, T['alpha_upper'], 0, nd, len(vs_noop), len(O_sub), len(textdiff), len(S4), T['random_control']['count'], …)` と並んでおり、7 番目に置かれた定数 `0` が以降の引数を一つずつ左へ送っている。結果として「記述」には定数 0 が、「無操作との差」には記述の総数 `nd`（=17）が、以下ひとつずつずれた値が入る。

裏づけを二つ。(i) `tools/make_contrasts_B.py` の 188 行は `assert len(ids) == len(set(ids)), '対比の id が重複'` であり、生成器は id の一意性を止めどころにしている。つまり「id 重複 3」は、生成器自身が assert で禁じている状態を印字している。(ii) 草案6B §2.3 の本文は「ランダム方向は層ごとにノルムを合わせて **3 本**引き」と書いており、同じ文書の §6 の「ランダム方向 **1** 本」と表面で矛盾している。

なぜ検査を通ったか。`records/B/numbers-lint-draft6B.md` は「登録検査（文書 `design/design-stageB-draft6.md`・**§6 と §6-補 を除く**）: 未登録 0」と印字する。転記行は検査の対象外である。また 0・1・3・4・8・17 はいずれも正本のどこかに実在する値なので、仮に検査しても「未登録」では捕まらない。

**(c) なぜ問題か**。(i) 転記行 B は、読み手が記述の族の規模を知る唯一の場所である（§2.2 が「対比と腕の数…は〔転記行 B・§6〕」と本文から送っている）。記述の対比が 17 本あるのに「記述 0」と読める。(ii) S4 の反証は本設計で唯一の反証の場だが、その本数が 1 本であることが 4 本と印字される。(iii) 「id 重複 3」は、正本に重複した対比 id が三つある——つまり集計器が同じ行を三重に数えうる——と読める記述で、事実と逆である。凍結のときにこの行がそのまま凍結本文に入ると、凍結物の記述が正本と食い違う。(iv) 依頼文 §0 が探すよう求めた型そのものである（書いてあることが器の実際の振る舞いと合っていない）。

**(d) 直し方の案**。(i) `design_facts_B.py` の `F['B']` の引数から定数 `0` を外し、先頭を `nd` にする。`id 重複` は `len(ids) - len(set(ids))` を実際に数えて渡す（assert があるので常に 0 になるが、印字の出所を式にする）。(ii) 転記行を作り直し、草案6B を組み立て直す。(iii) 構造の直しとして、生成器の各書式文字列について「書式欄の個数と引数の個数が一致し、各欄のラベルと引数の出所を対応表で持つ」自己検査を `_selftest` に足す。いまの検査は「文字列リテラルに構造でない数が無いか」しか見ておらず、ラベルと値の対応は見ていない。(iv) `numbers_lint.py` の除外（§6 と §6-補）は、転記行が機械生成だから検査しないという前提に立っている。転記行の値を設計事実 JSON の `data` から突き合わせる検査（md の数と `F[X]['data']` の数の照合）を足せば、この型のずれは機械で止まる。

### 重大2. 「同値の帯 ±9.8 pt」と「最良を選ぶ確率 0.713」は、正本に書かれた選定規則の値ではない

**(a) 対象**: §6 転記行 C ／ §2.3 の選定 ／ 正本 `selection.pick`・`selection.equivalence_band` ／ `tools/design_facts_B.py` の `se_pt`・`band_pt`・`pick_prob`。依頼文 §1 の重点 2 に当たる。

**(b) 事実**。二つに分かれる。

**(b-1) 帯の大きさ。** 正本の定義は逐語で「最大の候補との差の 95% 区間（二項の差・正規近似）が零を含む候補を同値とする」である。ここで比べるのは *候補 i の低下幅* と *最大の候補の低下幅* の差であり、低下幅はそれ自体が二つの割合の差（`Onull+vrand` − `Onull+v`）なので、この量は **四つ**の割合から成る。調整走行は 3,600 ＝ 9 候補 × 2 腕 × n=100 × 抽出場面 2 なので、候補ごとに別の `Onull+vrand` 腕があり、四つは独立である（`Onull+vrand` を 9 候補で共有する設計ではない）。

正本の定数からの再計算（基底 ＝ 抽出場面の Onull の既測 (276+148)/(400+400) ＝ 0.530、腕あたり n＝200）:

- 一つの候補の低下幅の標準誤差 ＝ 100·√(2·0.53·0.47/200) ＝ **4.99 pt**（→ 1.96 倍 ＝ 9.78 pt）
- 最大の候補との差の標準誤差 ＝ 100·√(4·0.53·0.47/200) ＝ **7.06 pt**（→ 1.96 倍 ＝ **13.83 pt**）

転記行 C が印字する ±9.8 pt は前者、すなわち「一つの候補の低下幅が零と違うか」の区間であり、正本が定義した「最大の候補との差」の区間ではない。生成器の該当行も `se_pt = 100*math.sqrt(2*base_tune*(1-base_tune)/tune_n)`・`band_pt = 1.96*se_pt` で、係数は 2 である（4 ではない）。正しい帯は √2 倍広く、±13.8 pt である。

**(b-2) 選ぶ確率。** 生成器の `pick_prob` は `np.argmax(obs, axis=1) == best` を数えており、**純粋な argmax** の規則である。しかし正本 `selection.pick` の規則は「品質床に合格した層 × 係数のうち、操作有効性が最大のもの（**同値の帯の内側なら、係数の小さい方・層の浅い方**）」で、argmax のあとに帯と決まりが入る。本検分は同じ乱数の型（各候補について `Onull+v` と `Onull+vrand` をそれぞれ Bin(200, ·) から引き、低下幅を作る）で 200,000 回の模擬を回し、まず生成器の argmax の規則を再現したうえで、正本の規則を実装して比べた。

| 規則 | 「一つだけ真に 10 pt・他は零」 | 「零〜15 pt の等差」 |
|---|---|---|
| 純 argmax（転記行 C の印字） | 0.707（転記行 C は 0.713） | 0.443（転記行 C は 0.439） |
| 正本の規則・帯 ±9.8 pt | 真の最良の格子位置ごとに 0.120〜0.983（平均 0.336） | 0.033〜0.920（平均 0.164） |
| 正本の規則・帯 ±13.8 pt（正しい帯） | 0.029〜0.997（平均 0.204） | 0.005〜0.979（平均 0.125） |

（上段の二つが転記行 C の値とモンテカルロの誤差の内側で一致することで、本検分の模擬が生成器と同じ規則を再現していることを確かめた。生成器は 20,000 回で、その標準誤差は約 0.003 である。）

さらに、**帰無（全候補の真の効き目が零）のとき、選定はほぼ決まり手で決まる**。同値と判定される候補数の平均は帯 ±9.8 で 6.11 組・±13.8 で 7.85 組（9 組中）であり、選ばれる組の分布は:

| 帯 | 層 0.25・係数 0.5 | 層 0.50・係数 0.5 | 層 0.75・係数 0.5 | その他 |
|---|---|---|---|---|
| ±9.8 | 0.679 | 0.193 | 0.069 | 0.059 |
| ±13.8 | 0.873 | 0.098 | 0.019 | 0.010 |

（純 argmax なら一様に 0.111。）また「真に 10 pt 効く候補が、いちばん深い層 × いちばん大きい係数にある」場合、正本の規則がその候補を選ぶ確率は帯 ±9.8 で 0.120・±13.8 で 0.030 にすぎず、代わりに 層 0.25・係数 0.5 を 0.424／0.668 の確率で選ぶ。

**(c) なぜ問題か**。(i) 転記行 C は選定の質を表す唯一の数であり、依頼文の重点 2 はこの数の下で規則が壊れていないかを見よと言っている。その数が、実際に使う規則ではない規則の値である。(ii) 帯が √2 分狭いので、同値と判定される候補が実際より少なく見える。(iii) 決まり手（係数の小さい方・層の浅い方）が帯の広さのために選定をほぼ支配する。これは選定が「効き目が最も出る組を選ぶ規則」であるという §0-1 の自己申告および正本 `selection.coi_note` の定型と、実際の振る舞いが合っていないことを意味する。向きとしては起草者の引かれる向きの逆（最弱の介入に寄る）なので、起草者に有利な方向ではない。しかしその代償として、**本走行の検出力が転記行 D の前提（±15 pt が真にある）から外れる**。層 0.25・係数 0.5 は候補の中で最も弱い介入であり、転記行 D の 0.85〜0.95 という数はそこでは根拠を失う。(iv) 「係数の小さい方・層の浅い方」は優先順位が書かれていない。層 0.25・係数 2.0 と 層 0.5・係数 0.5 が同値のとき、係数を先に見るか層を先に見るかで結果が変わる（本検分は係数を先に見る読みで計算した）。

**(d) 直し方の案**。(i) 転記行 C の帯を、正本の定義（最大の候補との差）に合わせて四つの割合から出す。(ii) 転記行 C の「最良を選ぶ確率」を、正本 `selection.pick` の規則（帯と決まり手を含む）で計算し直し、真の最良が格子のどこにあるかで値が散ることを、最小・平均・最大で印字する。あるいは、(iii) 決まり手を「同値のときは係数の小さい方」から「同値のときは点推定が最大の組をそのまま採る（決まり手は帯の外の候補にのみ効く）」へ変え、帯は「選んだ組が唯一とは限らない」ことを開示するためだけに印字する規則にする。どちらを採るかは設計の判断なので登録者に諮る項目になる。(iv) 優先順位（係数が先か層が先か）を正本に書く。(v) 採否表 C50（採用）は「D4 で帯を用いる場合は**厳密分布**（または候補横断の最大統計量の置換分布）から出し、格子点を印字」と書いているが、正本 `equivalence_band` は「二項の差・**正規近似**」のままである（中11 として別項に立てる）。帯を作り直すときに同時に閉じるのがよい。

### 重大3. S4 の反証は、封印する予想の相手と、正本に登録された対比の相手が別である。加えて裁定の規則が無い

**(a) 対象**: §1-4・§2.4 の記述の族・§3 読み条項 (vi) ／ 正本 `descriptive_families.B_desc_S4`。依頼文 §1 の重点 3。

**(b) 事実**。封印する予想の逐語（草案 §1-4・正本 `B_desc_S4.question` とも同文）:

> (6b) の方向を S4 の Osec-Ncold に**加算しても下がらない、または上がる**、と凍結時に封印する。

一方、正本に登録された対比はただ一本で、`d:S4:Osec-Ncold+v6b~Osec-Ncold+vrand`（A ＝ `Osec-Ncold+v6b`・B ＝ `Osec-Ncold+vrand`）である。つまり予想は無操作（`Osec-Ncold`）を相手にした「下がる／下がらない」を言い、登録された対比はランダム方向を相手にしている。さらに `Osec-Ncold` は S4 の本走行の腕に載っており（`main_cells` に n=200 で実在する）、`by_scenario.S4` と `noop_by_scenario.S4` の両方に入っているのに、**この腕を含む対比は正本のどの族にも無い**。本検分が正本の全 33 対比の A と B を集めて `arms.main` と突き合わせたところ、どの対比にも現れない腕は `O` と `Osec-Ncold` の二つだった。

加えて、この族は「記述・族の外・p 非印字」であり、どれだけ下がれば「下がった」と数えるかの規則（pt の閾値・区間・検定）がどこにも無い。

**(c) なぜ問題か**。反証の場は、この設計で唯一「負ける」ことができる場所である。その場について、(i) 封印する文の相手（無操作）と登録された対比の相手（ランダム方向）が違うので、データが出たあとにどちらで読むかを選べる。(ii) 裁定の規則が無いので、下がり幅がいくつなら外れたのかを、率を見てから決めることになる。依頼文 §2 の「どちらの向きに転んでも『効いた』と読めてしまう配線になっていないか」に、この一点が当たる。向きとしては、予想は「下がらない」で、外れ（下がった）は起草者の引かれる向き (a)(b) と同じ側である。つまり規則が無いことの利得は起草者の側にある。

**(d) 直し方の案**。(i) 封印の文と登録された対比の相手を一致させる。無操作を相手にするなら `d:S4:Osec-Ncold+v6b~Osec-Ncold` を正本に足す（腕は既に走る）。ランダム方向を相手にするなら封印の文を「`Osec-Ncold+v6b` の率は `Osec-Ncold+vrand` の率を下回らない」に書き換える。両方を登録し、どちらでも同じ向きが出たときだけ「外れた」とする、という書き方でもよい。(ii) 「下がった」の裁定の規則を凍結時に数で書く。基底は 69/400 ＝ 0.1725 で床ではないので、記述のままでも幅は言える。参考として本検分が n=200 対 200・両側 Fisher・名目 0.05 で計算すると、−10 pt の検出力は 0.841、−15 pt は 1.000 である（この数は「記述に検定を当てたらどうか」の目安であり、記述の族に p を印字せよという意味ではない）。(iii) `O` の無操作腕（4 場面 × n=200 ＝ 800 試行）も同様に、どの対比にも現れない。§2.4 の「無操作との差は記述として併置する」が正本では `O-Ncold` と `Onull` の 8 本だけなので、`O` と `Osec-Ncold` の無操作を何に使うかを正本に書くか、走らせないかを決める（併せて軽微20 を見よ）。

### 重大4. ランダム方向のノルム一致の相手が書かれておらず、交差族と S4 では相手が違うベクトルになる

**(a) 対象**: §2.3 の最終項 ／ 正本 `random_control`（`norm_matched: true`・`per_layer: true`）・`directions`・`families.B_cross`・`descriptive_families.B_desc_S4`。依頼文 §1 の重点 3。

**(b) 事実**。草案は「ランダム方向は層ごとに**ノルムを合わせて** 3 本引き」と書き、正本は `norm_matched: true` と書くだけで、**何のノルムに合わせるか**を書いていない。正本の `directions` には四つの方向がある: `static`（h_O − h_Osec・確証族の v̂）・`loaded`（h_{O-Ncold} − h_{Osec-Ncold}・S4 の反証）・`Nk`（h_Nk − h_N・交差族の v̂）・`td`（h_Onull − h_N）。このうち `td` だけは「**ノルムを v̂ に合わせる**」と明記されている（`directions.td.def`）。

一方、`Onull+vrand` という一つの腕が、加算族（相手は `Onull+v`＝`static`）・交差族（相手は `Onull+vNk`＝`Nk`）・記述の td（相手は `Onull+vtd`）の三つで相手役を務める。`O-Ncold+vrand` は交差族（`Nk`）の相手、`O-Ncold-vrand` は減算族（`static`）と td の相手、`Osec-Ncold+vrand` は S4 の反証（`loaded`）の相手である。`static`・`Nk`・`loaded` は別々のベクトルなので、一般にノルムは異なる。

**(c) なぜ問題か**。v 対 v_random という対比の根拠は「同じ大きさの摂動を同じ場所に入れて、向きだけを変える」ことにある（§0-1 はこれを引力を打ち消す印として挙げている）。ノルム一致の相手が v̂（`static`）に固定されているなら、交差族と S4 の反証では**向きと大きさが同時に変わる**ので、有意差が出ても「Nk の向きがランダムと違う」とは言えず「大きさが違う」で説明がつく。有意差が出なくても、大きさが釣り合っていなかったのかもしれない。どちらに転んでも読める配線である。依頼文 §2 が名指しした点に当たる。

**(d) 直し方の案**。(i) 正本 `random_control` に「どの方向に合わせるか」を書く。素直なのは、比べる相手ごとに別のランダム腕を持つこと（`Onull+vrand(static)` と `Onull+vrand(Nk)`）だが、これは腕とセルを増やす。(ii) 増やさないなら、四つの方向を**抽出のあとに層ごとに単位ノルクに正規化し、係数（ノルム比）だけで大きさを決める**という規則を正本に置けば、ランダム方向も同じ係数で作れて一本で足りる。この場合 `directions.td` の「ノルムを v̂ に合わせる」は不要になる。(iii) どちらにせよ、凍結の前に四つの方向の層ごとのノルムを印字し（§2.11 は要約統計の公開を約束している）、一致しているかを記録に残す。

### 重大5. 品質床は v にしか当たらない。ランダム方向・Nk 方向・腕対の差方向の能力低下は門を通らない

**(a) 対象**: §2.5 ／ 正本 `quality_floor`（`arms: ["O-Ncold","Onull"]`・`operations: ["−v", "＋v"]`・`cells: 18`・`partner: 同じ腕の無操作`）・`gate1`。

**(b) 事実**。品質床のセルは 18 ＝ 2 腕 × 層 3 × 係数 3 で、操作は `−v`（減算族の土台）と `＋v`（加算族の土台）の二つだけである。転記行 A の 4,000 問 ＝ 200 問 × (18 セル ＋ 無操作 2) も、これと一致する（自分で数えて一致を確かめた）。`vrand`・`vNk`・`vtd` を当てたセルは一つも無い。

**(c) なぜ問題か**。確証の対比はすべて「v 対 v_random」で、両腕とも介入を受けている。品質床の役目は、選んだ層 × 係数が課題の遂行を壊していないことを確かめることだが、片方の腕（v）しか確かめない。ノルムを合わせても能力低下が同じになるとは限らない。もし v_random の方が大きく壊れて、書式外や意味の通らない出力が増え、それが破局の判定に影響すれば、「v ≠ v_random」は向きの違いではなく壊れ方の違いを測ることになる。§2.12 の `format_fail_denominator`（書式外は分母に入り破局に数えない）があるので、壊れた腕は破局率が下がる側に動く。加算族は「v の方が下がる」を期待する族なので、v_random が壊れていない場合よりも差が出にくく、逆に v が壊れていれば差が出やすい。どちらの向きにも効き、しかも門で止まらない。

**(d) 直し方の案**。(i) 品質床に `＋vrand`・`−vrand` を足す（セルは 18 → 36、問は 4,000 → 7,600。裁定 D61 が試行数を削らないと定めているので、増やす向きの提案は費用の再申告を伴う）。(ii) 増やさないなら、選ばれた **一つの**層 × 係数についてだけ、`vrand`・`vNk`・`vtd` を品質床に当てる（セルは 18 ＋ 4 ＝ 22、問は 4,400。選定のあと・本走行の前に置ける）。(iii) いずれにせよ、確証の対比の両腕の書式外率・`refuse` 率・応答様式の差を、無操作を基準にして報告に機械で併置する規則を正本に置く（いまは `refuse` 門と様式門が名目有意の対比にだけ当たるので、非有意の対比の壊れ方は札にも記述にも出ない）。

理由。(i) 重大1 は、凍結物に入る予定の機械の区画が、七つの数を取り違えたまま印字している事実であり、直さずに次の段（系統内外の検分）へ回すと、検分者が誤った数を前提に読むことになる。(ii) 重大2 は依頼文の重点 2 そのものに当たり、転記行 C の数が正本の選定規則の数ではないため、いまの草案では「選定の雑音の下で規則が壊れていないか」を読者が判断できない。(iii) 重大3・4・5 と中6 は依頼文の重点 3 に当たり、いずれも「どちらに転んでも読める」余地を残す配線である。(iv) 中8・中9 は、登録された記述の問いを支える素材・保存が無いという食い違いで、凍結すると答えられない問いが凍結本文に残る。

ただし、設計の骨格（プロンプトの最終トークンへの再設計・確証を v 対 v_random に固定したこと・両側での登録・門1 を品質床に限ったこと・記録先行公開）は作り直しを要しないと見る。上の所見は正本と転記行と生成器の直しで閉じられ、増える試行は中6（零）・重大3 (i)（零・腕は既に走る）・中9（零・保存量だけ）・重大5（案 (ii) なら 400 問）に留まる。重大5 の案 (i) を採る場合と、中8 の案 (ii) を採る場合だけが費用に触れるので、その二つは登録者の裁定に上げるのが適当だと考える。

差し戻しの後は、同じ草案を再び系統内で読み直すより、直した版を系統外（非 Claude 系）へ先に回すほうがよいと考える。本検分は起草者と同一系列であり、重大1 のような取り違えを見つけられたのは、転記行の数を正本から数え直したからで、読みの力によるものではない。
