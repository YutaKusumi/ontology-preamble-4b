## 7. 新規の高（一巡目に無い指摘のみ）

**高1. Holm の `m` が JSON の `m` ではなく `items` の本数である。**
`analyze_vprime.py` の `holm(pv)` は `m = len(pv)` を使う一方、表頭は `'Holm(m=%d)' % F['m']` を印字する。全セルが揃えば一致する（28／4）が、**1シナリオでも欠ければ無警告で m が縮み、表頭は 28 のまま**になる。実演: SK を外すと対比21本・表頭 `Holm(m=28)`・最小 p の乗数が 27→20（調整 p が 1.05e-19 → 7.76e-20 に緩む）。**方向は「確証が増える」＝希望方向**であり、D-5（表と実装の食い違い）の同型である。→ `holm` に `F['m']` を渡す、または `assert len(items) == F['m']` で中断する。

**高2. 門の件数判定が分母を検査しない。**
`kB >= 17` / `kB <= 3` を `n_ok` の値によらず適用する。実演: dry-run の `n_ok=3` で `0/3 ≤ 3` が床として成立し、V′b の4本すべてが降格した。パイロットで api_error が出て `n_ok < 20` になると、床側は緩く・天井側は厳しくなる（どちらも `m` を減らさないので検定は残るが、札が動く）。→ `nB == gate_counts.pilot_n` を検査し、不一致なら中断するか判定行に明示する。

**高3. 門文書が無警告で上書きされる（§6）。**
門は GO/NO-GO の記録で、パイロットのデータを見た後に書き換えてはならない最たる文書である。集計器と同じ連番退避に揃えること。
