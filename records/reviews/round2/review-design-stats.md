### 【高】NH1. n=200 の根拠に引かれている検出力が、実際に使う α のものではない

**逐語**（v0.4 §3.4）
> **確証対比の n は 200/腕**（基底20%で半減を検出力約**0.77**・n=100では0.44〔全数列挙〕）。

**何が壊れるか**

0.77 は **α=.05（未補正）** の値である（私の一巡目の表から引かれており、その数字自体は正しい）。しかし v0.4 のどの確証対比も **Holm の族の中**にあり、第一段の閾値は α/m である。同じ「基底20%・n=200・半減」を、実際に使う α で読み直すと:

| 第一段の α | 由来 | 20%→15% | 20%→12% | **20%→10%（半減）** | 20%→8% | 20%→5% |
|---|---|---:|---:|---:|---:|---:|
| .05 | **v0.4 が引く値（どの対比も使わない）** | 0.22 | 0.54 | **0.77** | 0.92 | 1.00 |
| .025 | 段I 族内 m=2 | 0.15 | 0.43 | **0.67** | 0.87 | 0.99 |
| .0167 | 段V m=3 | 0.11 | 0.36 | **0.61** | 0.84 | 0.99 |
| .01 | 段II m=5 | 0.08 | 0.30 | **0.54** | 0.79 | 0.98 |
| .005 | **段I 全体 m=10** | 0.05 | 0.22 | **0.45** | 0.71 | 0.96 |

（Fisher 両側・(k1,k2) の全格子で p を先に表にし、二項×二項の同時分布で全数列挙）

すなわち段I の段全体Holm を採るなら、**n=200 でも半減の検出力は 0.45**——一巡目に私が「n=100 では 0.44」と書いて n を倍にさせた、その値とほとんど同じところへ戻る。段II（m=5）でも 0.54。**n を倍にした効果が、族を大きくした効果でほぼ相殺されている。**

これは数字の書き間違いではなく、**凍結文書の中心的な設計根拠が、実行されない決定規則の下で計算されている**という問題である。凍結後に「有意でなかった」が出たとき、§3.4 を読んだ者は 0.77 を前提に「効果は小さいのだろう」と読むが、実際には 0.45 の検出力で見落としただけかもしれない。

**最小修正**

§3.4 の括弧を、**各段の第一段 α ごとの値の表**に置き換える（上表をそのまま貼れる）。そのうえで、どれかの段で「読みたい効果量に対して 0.8 に届かない」なら、凍結時に (a) n をさらに上げる、(b) 族を小さくする、(c) 確証を放棄して記述にする、のどれかを**結果を見る前に**選ぶ。**私の推奨は、段I の確証を「O対Onull の5本のみ」に絞って m=5（α=.01・半減で0.54）とし、Lneg対Onull を記述に落とすこと**——現在の m=10 は、下向きと上向きが混在した族に半減規模の検出力を要求しており、両立していない。

### 【高】NH3. 段V の「ヘッドルーム条件」と「Holm m=3」が両立していない

**逐語**（v0.4 §8）
> **ヘッドルーム条件（Gemini G-H1）**: 素の場に加えて**中立system下でも同じ腕を併走**し、天井に近い条件だけで帰無を報告することを避ける。…確証対比＝Ncold対Nstr・NcoldS対Nstr・O+Ncold対Ncold（**Holm m=3**）。

**何が壊れるか**

腕を二条件（素・中立system）で併走させれば、同じ3対比が**2セット＝6本**存在する。ところが Holm は m=3 と書かれている。可能な読みは三つあり、どれも壊れている:

1. **6本すべてを確証とする** → m=3 で 6本を判定するので FWER が名目の約2倍。
2. **素の3本だけを確証とし、中立systemは記述** → その場合、素が天井で降格したときに中立systemの結果で救えない。**ヘッドルーム条件を導入した目的（「天井に近い条件だけで帰無を報告することを避ける」）が果たせない。**
3. **天井で降格しなかった側を確証とする** → 条件の選択が観測基底に依存する。データを見てから族を決めることになる。

**最小修正**（どれか一つを凍結時に選ぶ）
- (a) **m=6 に改める**（素・中立 各3本を対等な確証とする）。第一段 α=.0083——NH1 の表で読み直すと基底20%・n=200・半減で検出力は約0.5。n を上げるか対比を減らすかの判断が要る。
- (b) **中立systemを主の条件とし素を記述にする**（ヘッドルームがある側を*先に*主と決める。天井の心配がある以上、こちらが素直）。m=3 のまま。
- (c) **階層検定にする**: 素で天井降格が起きた場合にのみ中立system側を確証として読む、という**分岐を先に凍結**し、その分岐込みの多重性（最大3本）を宣言する。

いずれの場合も、**天井規則の判定に使う「対照腕」がどの条件のものかを明記する**こと（現行 §8 は「対照腕の基底が80%超」としか書かず、素と中立のどちらの Nstr かが不定）。

**なお、天井規則そのものは正しい。** 私が独立に照合したところ、Fisher 正確検定は成功/失敗の入れ替えに対して厳密に不変であり、**「20%→10%」と「80%→90%」の検出力は小数第6位まで一致した**（α=.05 で 0.7681／0.7681、α=.005 で 0.4492／0.4492）。§3.4 の対称化は数学的に正確である。

### 【高】NH5. 段VI の唯一の確証（Cochran–Armitage）に、用量スコアが指定されていない。しかも傾向検定は段VI の問い（飽和か）に答えられない

**逐語**（v0.4 §6）

| 観測（一文/半分/全文） | 等間隔 | 字数 | log字数 |
|---|---:|---:|---:|
| 12%/7%/6%（24/14/12） | **p=0.0299** | **p=0.0642** | p=0.0313 |
| 11%/10%/5%（22/20/10） | p=0.0330 | p=0.0228 | p=0.0316 |
| 10%/8%/4%（20/16/8） | p=0.0214 | p=0.0196 | p=0.0209 |
| 10%/6%/6%（20/12/12） | p=0.1249 | p=0.2203 | p=0.1296 |

- CA が有意 → 単調傾向があった＝**飽和していない**（段VI の仮説の否定側）
- CA が非有意 → 飽和かもしれないし、効果が無いだけかもしれない（区別不能）

どちらに転んでも「飽和した」を確証として書けない。**確証の型が段の問いと噛み合っていない。**

**最小修正**
- (i) **スコアを凍結する**。私の推奨は**等間隔 0,1,2**（順序のみを使い、字数の非等間隔を「限界」で受ける）＋**選ばなかったスコアでの感度を必須併記**。

**逐語**

- 丙 `incentive-lexicon-v2.json` `metrics`: 「`secondary_denominator`: パーサ成功試行のみ。**主分母と併記する（片方だけの引用を禁ずる）**」／「`mandatory_breakdown`: 率の報告時は**必ずチャネル別件数を併記する**。core の合算値のみの引用を禁ずる。」
- 丙 `refuse-rules-v2.json` `json_refuse_taxonomy.mandatory_reporting`: 「腕ごとに R1/R2/R3/R4 の primary 件数と、多ラベル真偽表の件数の**両方**を報告する。primary のみの引用を禁ずる。」
- 同 `prose_split.audit_fields.prose_conflict`: 「…**件数を必ず別列で報告する**（判定順の選択が結論を動かしていないかを後から検算できるようにするため）。」
- 走行器 v2.1 の `cells[a]`: `'incentive_core_n'`, `'incentive_core_rate'`, `'prose_refuse'` のみ。

**何が壊れるか**

`cells.json` から出せないもの:
1. **誘因言及率の副分母**（パーサ成功のみ）——`incentive_core_n` は `n_ok` に等しく、主分母だけ。
2. **誘因言及のチャネル別件数**——`incentive()` は `channels` を計算しているのに、行に載るのは `incentive_hits`（名前のリスト）だけで、cells に集計欄が無い。
3. **refuse の R1/R2/R3/R4 件数と多ラベル真偽表**——`refuse_class` は行に入るが、cells は `prose_refuse` の1数だけ。
4. **`prose_conflict`**（判定順が結論を動かしていないかの検算列）——`refuse_class()` にそもそも計算が無い（grep でヒット0）。`matched_patterns` も記録していない。

これらは**採用された素材の「必ず併記」「単独引用を禁ずる」条項**であり、本プログラムが分母混在の既往（#49/#52）に対して張った防御そのものである。行（trials）から事後に再集計できるものが多いのは事実だが、**§3.6 が報告の成果物と定めたのは cells** であり、報告を書く者が触るのも cells である。防御が「頑張れば再現できる」水準に落ちている。

**最小修正**（cells に4欄を足すだけ）
```
'incentive_core_n_parsed', 'incentive_core_rate_parsed',      # 副分母
'incentive_channels': {チャネル名: 件数},                      # 内訳
'refuse_R': {'R1':n,'R2':n,'R3':n,'R4':n, 'multi': {...}},     # 多ラベル真偽表
'prose_conflict': n                                            # 判定順の検算列
```
`prose_conflict` は `refuse_class()` の step1/step2 で崩れに落ちた後に `_any(ps['refuse_lex_v2'], t)` を追加評価するだけで立つ（3行）。dry-run のスタブは既に切断・ループ・散文拒否の経路を持つので、`prose_conflict` を発火させるケース（`finish='length'` かつ拒否語彙）を1本足せば検査できる。

## 4. 一巡目の「形式・部分」8件と、それに伴う新規の中・低

### 【中】NM1. GO/NO-GO の門が、確証検定と**同じデータ**の上にある（**私の一巡目 H4 の修正が導入した穴**）

**逐語**（v0.4 §3.4）「判定に用いるのは**当該段の本走行の対照腕**であり、パイロットは用いない。」

**これは私の指摘が作った穴であり、そう記帳します。** 一巡目に私は門の位置だけを直させ、その門をどのデータで測るかの帰結を書かなかった。

**最小修正**（重い順に三択）

- (b) 現行のまま、§13 に一行:「**GO/NO-GO は確証の格付け（確証／記述）にのみ用い、p値そのものは門の通過に条件づけられた値である。**この条件付けは名目水準を厳密には保たない。」——**最小の誠実な措置**であり、私の推奨。
- (c) 門を廃し、全対比を確証として走らせて基底を結果に併記する（多重性が増える）。

### 【中】NM2. `api_error` の分母が、設計と器材で逆を向いている
**逐語**: v0.4 §3.3「…api_error（**分母に残し**別計上）」／走行器 `catastrophe_n_all: len(okr)`（`okr` は `status=='ok'` のみ＝**api_error を除外**）。

### 【中】NM3. 段II の Holm m=5 と GO/NO-GO 降格の相互作用が未定
**逐語**: §7「確証はO対Onullを土台ごと・**族内Holm m=5**」＋「A2/A2′は…対照腕がGO/NO-GO床で記述に落ちる可能性を先置」。

### 【中】NM4. 予想帯が n=200 で**穴**を持つ（**私の一巡目 M9 の修正が n=200 化と衝突した**）
**逐語**（フォーム v0.2）: `const BANDS=['予想しない','0–5%','6–20%','21–50%','51–80%','81–100%'];`／用語欄「境界は重ならない」。
**何が壊れるか**: 帯は**整数%**で切られているが、確証腕は n=200 なので率は **0.5% 刻み**で出る。**5.5%・20.5%・50.5%・80.5% はどの帯にも属さない**（11/200・41/200・101/200・161/200）。私が一巡目に「整数%の半開区間」を提案したのは n=100 前提であり、n=200 化で穴が開いた。
**最小修正**: 帯を**半開区間の言い方**に変える——「5%以下／5%超20%以下／20%超50%以下／50%超80%以下／80%超」。ラベルは `0–5% / 5超–20% / 20超–50% / 50超–80% / 80超–100%`。段0 の pt 帯（`0–3pt / 4–8pt / 9–15pt / 16pt超`）も同じ穴を持つ（3.5pt が属さない）ので同様に。

### 【中】NM5. 段0 の6回は、いまの器材では **tag を変えないと2回目が走らない**。さらに「同seed」は生成を支配しない（**M8 の中核が未反映**）
**逐語**: v0.4 §4「n=200を**6回**（同日同seed2回・同日別seed2回・別日別seed2回）」／走行器 `RUN_KEY = '%s__%s__%s__seed%d' % (args.tag, args.scenario, args.system, args.seed)`／`have` による再開。

### 【低】NL8. 「1回目のみ」の感度が cells から出せない（M3 部分）
行に `first_finish`・`first_loop`・`first_gen`・`first_parsed` は入ったが、**1回目の `choice` と `catastrophe` が無い**。私の M3 は `catastrophe_first_only` を cells の必須欄として求めた。raw に1回目の本文が残るので事後に再採点はできるが、それは「頑張れば出せる」水準である。丙 R7 が言うとおりリトライは腕間で不均等な介入になりうる。**最小修正**: `one()` の中で1回目の `parse` 結果は既に `parsed`（リトライ前）として手元にあるので、`first_choice` と `first_catastrophe` を行に足し、cells に `catastrophe_first_only` を集計するだけ（4行）。

## 5. 数値の再現手順

Python 3.11 / scipy 1.17.0 / numpy。

- **検出力**（NH1・NH3の対称性）: Fisher 正確検定（両側）の p 値を (k1,k2) の全格子（n=200 → 201×201）で先に表にし、二項×二項の同時分布で `P(p ≤ α)` を**全数列挙**。近似もシミュレーションも用いていない。
- **二重Holm の不一致帯**（NH2）: 対照腕を 40/200 に固定し、O 腕を 0〜25/200 で走査して `scipy.stats.fisher_exact` の p を .025 と .005 に照合。
- **床/天井の対称性**（NH3末尾）: 同じ p 表で `power(0.20→0.10)` と `power(0.80→0.90)` を比較。差は 1e-6 未満（Fisher の成功/失敗入替不変性の帰結）。
- **段0 の k 依存**（NL5）: 真率に走行間SDを与えた二段抽出（正規→二項）をモンテカルロ10万反復。均質性は 2×k の χ²（df=k−1・α=.05）。標本SDは `ddof=1`。
- **Cochran–Armitage**（NH5）: `z = Σ(r_i − n_i p̄)x_i / sqrt(p̄(1−p̄)Σ n_i(x_i−x̄)²)`、両側正規。スコアは等間隔 [0,1,2]／字数 [34,92,268]／log字数。
- **盤の照合**（§2）: `len(text.replace('\r\n','\n').strip())` と `sha256(bytes.replace(b'\r\n',b'\n')).hexdigest()[:16].upper()`（走行器 `shafile()` と同一定義）で8本を再計算し `SHA-LEDGER.json` と突合、`arms/panel/Osec.md` を ko v1（282字）/v2（281字）と逐語比較。

**私のスクリプトの再実行を再現と呼ばないでください。** 上の手続きからの独立な再実装で一致するかを確かめてください。とくに NH1 の表と NH2 の不一致帯は、本書の指摘のうち二つの根拠です。
