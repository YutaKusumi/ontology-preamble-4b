## Q1 問いと答えの届く範囲

問いは一つに絞れており、行動と系譜に届かない、という上限自体は明確である。ただし「答えられないこと」に抜けがあり、§9 の読みの規則が §0 の上限を守り切らない。

2. 節: §0（答えられないこと）・§3.5
3. 引用: 「- 直答の型の様式を教師強制で置くこと自体が表現に与える影響。」
4. 問題: 最も近い行はこれだけで、空の思考の欄は弱点には書いてあるが、「答えられないこと」に入っていない。Gemma では主位置が空の思考の閉じであり、書き出しはその直後の教師強制である。方向の効き目と、空の欄を置いたこと・その閉じトークンから帯を始めたこととは、この登録の対比では分離できない。加えて、softcap 後の部分集合の対数オッズを、softcap の無い層三の対数オッズや、自由生成の選択と同じ量として読めないことも、一覧に無い。採点器の妥当性が Gemma の応答では未検証であることも、§4.4 の限界にはあるが、頭の一覧に無い。(iii) と q7 の答えは、その未検証の採点に乗る。

## Q3 加える量（案 2）

2-A の式は、層三の相対注入の定義に対して代数的に合っている。係数＝層三の比 ÷（‖v̂‖ ÷ ‖h‖）は、注入ノルムを ‖h‖ のその比倍にする。2-B より、残差ノルムに対する倍率を機種間で混ぜない、という狭い目的には妥当である。その目的は、§8 の二機種の並べを正当化しない。見落としている害がある。

### F8
1. 重さ: 重大
2. 節: §1（案 2）・§10
3. 引用: 「係数＝層三の比 ÷（‖v̂‖ ÷ ‖h‖）を、相 extract の後に器が出し、転記行 D に印字する。値を見て選ぶ余地を残さない（式で決まる）。」
4. 問題: 式で決まることと、その係数が測定として使えることは別である。‖v̂‖/‖h‖ が層三よりずっと小さいと係数は大きくなり、bf16 の加算と softcap（cap × tanh(z ÷ cap)）の飽和の側に寄る。大きいと係数は小さくなり、効き目は揺れの床に埋まる。どちらも「等方と区別できなかった」に見えうるが、量の失敗である。本文に係数の停止範囲が無い。§10 の「残差のノルムの意味が機種で同じとは限らない」は正しいが、softcap が対数オッズの尺度を層三と別に圧縮すること、八腕平均の ‖h‖ が O-Ncold や Onull のその升目のノルムと違うこと（N と Nk は本文トークン数が 0 と 9、O 系は 170 超）、方向ごとに bf16 の刻みで実効の大きさが変わりうること、は書いていない。抽出の後に係数を見て案を選び直す余地を残さない、のは正しい。残していない代わりに、病的な係数でも札まで進む。
5. 直し方: 値を見る前に、機械の停止だけを置く。例: 係数が予め置いた区間の外、または注入ノルムが選んだ層の ‖h‖ に対して予め置いた比の外、または ‖v̂‖ が数値の床以下、なら札を付けずに「この加える量では測れなかった」と閉じる。区間は抽出の前に凍結し、抽出の値で動かさない。§8 の揺れの広さを層三と並べる文には、尺度が softcap 後の対数オッズであり、比をそろえても尺度はそろわない、を同じ文に義務づける。

## Q5 札と帰無

割合の両側裾、Holm、二つ目の札の「中心は比べる相手の中央値」「同値は上回らない」、両方の向き、兄弟対の除き方は、線形性や Qwen の次元を仮定していない。手続きとしては Gemma でも働く。働き方を本文だけから一意に実装できず、高次元では等方の棒がさらに低い。

2. 節: §4.1・§5
3. 引用: 「**偶然の目安**: 層三の `nulls.real.chance_note` と同じ式で、B′ の行の数から出す。」
4. 問題: 層三の目安は、v̂ 行（向きまで 48）と Nk 行（向きまで 54）の混成と、十六行から出ている。行の数だけで倍率を掛けると、外した行がどちらの族かで目安がずれる。「同じ式」が、比べる相手の数を方向ごとに入れる式なのか、層三の 0.3087 を縮小する式なのか、本文では決まらない。別に、等方の方向は凍結の `blens_core.iso_directions` と書くが、次元を Gemma の隠れ次元にする、と本文に無い。Qwen の 2560 で引くと帰無が成り立たない。両方の向きも、Onull は主の組に + しか無い。層三は、主の組に無い符号の順伝播を足して、升目ごとに一つの比べる相手（符号に依らない）を作る。B′ は「両方の向き」と書くだけで、その追加の順伝播を §3.3 に書いていない。‖v̂‖ が数値的に零のときのノルム合わせの停止も無い。等方の本数を 1999 のままにするのは、次元が 5376 でも手続きとしては壊れない。ただし等方はデータ部分空間にさらに当たりにくく、低い棒は層三より低い。同じ〔等方の外〕でも、層三の札と同じ強さではない。
5. 直し方: 偶然の目安は、残った行について、方向ごとの比べる相手の数（除き方は層三の `comparators_oriented`）から計算し、層三の定数を倍率で使わない、と式を書き下ろす。等方の次元は抽出した活性の次元と一致することを assert する。両方の向きの追加順伝播を、バッチの数に含めて転記行 E の定義に書く。‖v̂‖ の退化は F8 の停止に含める。§10 に、等方の棒は層三より低い、と書く。

## Q6 記述と読みの規則

柵はあるが、掛かる範囲が札の数に偏っており、足りない。

### F15
1. 重さ: 中
2. 節: §8・§9・§11
3. 引用: 「層三と B′ の札の数を並べるときは、行の形・加える量の決め方・床の余白の扱いが違うことを同じ文に書く。」
4. 問題: 同じ文の義務は札の数だけである。§8 は揺れの広さの表と順位相関を、層三の公開の記録と並べる。q6 はその順位相関の符号を予想させる。予想を採点する以上、符号は結果として書かれる。しかしその文に、系譜・規模・トークナイザ・空の思考の欄・softcap・加える量の式が一緒に違う、を義務づけていない。禁止は「系譜の違いの効き目として読まない」に狭く、規模やトークナイザの効き目として読むことは、字面では禁じていない。行動の下見の率を、公開済みの段階 B の無操作の率と並べることも禁じていない。機根以外の性質の語（頑健、効いた、再現）の走査一覧も、§9 には無い。
5. 直し方: 二機種の数が同じ文に出るすべての文（札の数、揺れの広さ、順位相関、行動の率）に、同じ但し書きを義務づける。禁止を「系譜・規模・トークナイザ・仕様のどれか一つの効き目としても読まない」に広げる。q6 の採点文を先に書き、「符号は記述であり、仮説の支持とは書かない」とする。層三の禁止語一覧を、門に関する語を除いて走査に入れる。

## Q7 限界と利益相反

片道に結論を固定する仕掛けではない。開示は事実に合っている。それでも、区別できる側と、機種間の違いが出る側に寄る選択が残っており、限界の列挙は足りない。

### F16
1. 重さ: 中
2. 節: §4.3・§10・§15
3. 引用: 「コーディネータは、Gemma で区別できる行が出て A を行う理由が強まる側と、層三と同じく区別できない側の両方に引かれる。二つの機種の揺れの広さの違いを見つけたい向き（登録者の仮説）にも引かれる。」
4. 問題: 両側に引かれる、という開示は、中立であることの証拠にはならない。5-C は、層三の唯一の等方の外が床の近くにあった、と書いた上で、その種の升目を Holm に残す。外す（5-A）より「区別できた」が一つでも出やすい。理由は層三との比べやすさであり、比べやすさは登録者の仮説（機種で応じ方が違う）の記述にも役立つ。十六行は Gemma の事前の族ではなく、段階 B の確証族の移植である。どの行を見るかも、層三の結果を見た後の注意に寄る。限界のうち、本文が「そのまま当てはまる」とするのは、読み取り・写し・量・等方の低い棒・実在の差の相関・行の非独立、だけである。落ちているのは、softcap、層の種類、bf16 の方向ごとの実効量、係数の無制限、等方の棒が層三より低いこと、採点器、q7 が試行 40 では入れ替わりうること、主の行が移植であること、である。§10 の「思考の欄を空にした形だけを見る」は必要だが、F1 の分離不能より弱い。
5. 直し方: §15 に、5-C と十六行の移植は、区別が一つ出る側と、層三と同じ形で並べる側に有利である、と書く。中立化は開示ではなく F11 の主文の義務で行う。§10 に上の落ちている限界を足す。揺れの広さの指標は、今書いてある四つに限り、Gemma の値を見た後に指標を足さない。

## Q8 器と確かめ

下調べが拾った transformers 5 と Gemma 4 の差（チャットの型、層の道、最後の層と正規化、softcap、居残るフック、`apply_chat` の戻り、近道 API の欠如）は、器の合成データの確かめまでは届いている。凍結の前に足すべき確かめが残っている。合成データは小さな乱数の float32 で、出口の差が 0 になっている。実機の bf16 を代表しない。

### F17
1. 重さ: 重大
2. 節: §12・§3.2
3. 引用: 「**凍結の前の確かめ**（層三までの教訓）: 読み手の器が求める升目 ⊆ 書き手の器が書く升目の掃き出し（§0-28）・正本と凍結の本文が求める出力 ⊆ 器の出力の掃き出し（§0-37）・凍結物のすべてのファイルに手元の道筋の掃き出し（§0-51）・版のピン（§0-42）・表の縦棒と注の口（§0-48）・B′ のフックの数え方（transformers 5 の居残るフックを数えない・`bprime_gemma` v0.1）・G4 の確かめ。」
4. 問題: この一覧に、実機の重みでの読み取り経路の確かめが無い。足すべきものは次である。場面の文を使わない同じ長さの列で、float32 の正規化・共有の語彙行列・softcap を一度だけ通した値が、模型の出口（bf16）とどれだけ違うかを測り、`logit_tol` をその記録に結びつける。正規化を二度掛けると落ちること、softcap を抜くと落ちること、を実機でも確かめる（小さな模型の T3・T4 の型）。選ぶ層ではフックの出力と抽出が一致し、最後の層では `hidden_states` の最後と一致しないこと。`Gemma4RMSNorm` が 1＋重みではないこと。画像の塔を載せず、層の道が `model.language_model.layers` であること。G4 上で台帳のトークン列と主位置 `<channel|>` を再照合すること。生成は、場面を使わない列で、思考を出さないこと、11-A の標本化が実際に掛かること、出力の上限で止まることを、行動の下見の前に煙試験する。採点の合成応答に、空の思考の漏れ、JSON の複数、見出し、上限での打ち切り、refuse、量零の (a)、を含める。独立の再計算の二段目の許容は、近道の許容の写しではなく、バッチの違いの床から定義し直す。これらを欠くと、最初の失敗が F13 のやり直しに入り、読み取りの定義を見た後に直す道が開く。
5. 直し方: 上を「凍結の前の確かめ」に箇条で入れ、落ちたら凍結しない。場面の出力と読み取りの値は、この確かめでは印字しない。

## Q9 最も重い弱点

測定の位置が、Gemma の既定が置く空の思考の閉じの直後に、雛形の頭（その続きは a）を教師強制した位置に固定されていることである。層三の十六行・下見の閾値・札の語・帯を「同じ」として載せると、この別の量への答えが、層三と同じ問いへの答えに見える。区別できてもできなくても、空の欄・写しの手がかり・softcap・無制限の係数から分離できない。5-C は床の行を Holm に残し、§9 は印を主文に要求しないので、脆い一行が「区別できた」になりうる。これが最も重い。
