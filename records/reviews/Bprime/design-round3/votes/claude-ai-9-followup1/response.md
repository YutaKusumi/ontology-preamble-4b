## 1. 指摘 1 について

**推し**

一つ目と二つ目を一組で推します。人の確認を起動器の機械の確かめに置き換え、「進まないと決めたとき」の文を消す案です。確認という操作が残る限り、「確認しない」「進まない」という分かれ道が残るためです。

三つ目は、単独では推しません。ただ、人が次の段を起動しないことは器では防げません。そのときの扱いを決めておくために、止めは「閉じる形」に限って残すことを推します（下の「日が過ぎたとき」と同じ型）。

草案6 の元の文は次のとおりです（`design-Bprime-draft6.md` §2）。
- 「確認は記録の形の項目（ファイルがそろう・SHA が合う・凍結した確かめの合否・時刻）だけを見る。」
- 「抽出の直後に、抽出の記録（転記行 D・npz の SHA・係数・g との一致の合否）を時刻つきで作り、登録者の確認を得て公開の置き場に置いてから行動の下見に進む。」

**形の項目（閉じた一覧）**

行動の下見の起動器が、最初の順伝播の前に機械で確かめます。値は読みません。出所が草案6 に無い項は「私の足し」と書きます。記録の欄やファイルの名は、正本を組む段で決まるものです。

(一) ファイルがそろう
1. 抽出の記録（時刻つき）が公開の置き場にある。
2. その記録に、転記行 D・npz の SHA・係数・g との一致の合否の四つの欄がある。欄があるかだけを見て、中身の値は読まない（出所は §2 の上の文）。
3. 相 extract の起動器の印字がある。§2 の「起動器はセッションごとにドライバと CUDA の実行時の版を印字し」に当たる印字と、版・GPU の名。

(二) SHA が合う
4. 手元の npz の SHA が、記録に印字した npz の SHA と一致する。§2 に「npz そのものは置き場に入れない。」とあるので、手元のものを照らす。
5. 正本の SHA が、下見の前の凍結の記録のまま。
6. 相 extract の器と凍結の器の SHA が、下見の前の凍結の記録と一致する。読み込んだ後の属性も変わっていない（§2「起動器は凍結の器の SHA と、読み込んだ後の属性が変わっていないことを確かめる〔R38〕。」）。
7. 重みの断片の SHA が目録と一致する（§2「重みの断片の SHA-256 を、起動器が目録と照らす〔R37〕。」）。
8. 版のピンが文字列で完全に一致する（§2「凍結の時に、起動器が入れ直して文字列の完全な一致で確かめる（層三の型）。」）。

(三) 凍結した確かめの合否（すべて「通った」であること）
9. g との一致（§2「保存した g から同じ式（g × ‖v̂‖ ÷ ‖g‖）で作った値と相対の差 1e-12 の内で一致することを確かめる（ビットの一致は求めない）。」）。
10. 揃える前のノルムの確かめ（§1「揃える前のすべての方向（名前のある方向・実在の差）のノルムが有限で零でないことを assert し、落ちたら器の誤りとして止める（値に依らない）〔S19〕。」）。
11. 次元の一致（§4.1「等方の方向の次元が、抽出した活性の次元と一致することを assert する〔R23〕。」）。
12. 読み取りの値を作らないこと（§4.1「相 extract の器は、選んだ層より後を流さない（層 29 の出力で止め、出口の値を作らない）ことを assert にし、合成データで確かめる。」）。
13. 十六文脈の ‖h‖ の平均が有限で零でない（私の足し）。係数の分母に当たります。草案6 の assert は方向のノルムにだけ掛かり、‖h‖ には掛かっていないためです（推論: この assert が無いと、係数が有限であることが確かめの外になる）。

(四) 時刻
14. 抽出の記録の時刻が、封印の記録の時刻より後で、行動の下見の起動より前。公開の置き場の版の時刻で見る。
15. 相 extract の起動の記録が一つで、抽出の記録が指す走行と同じ（私の足し・検分の指摘 7 を採るとき）。二つあるときは、§4.5 の器の誤りの記録があること。

見ないもの: ‖v̂‖・‖h‖・係数・転記行 D の記述の値。

どれかが落ちたら起動器は止まり、§4.5 の器の誤りとして扱います。やり直しの範囲も §4.5 のとおりです。

**形の項目がそろっているのに、日が過ぎたとき**

この案では確認の操作が無くなります。そのため問いは「形の項目がそろっているのに、行動の下見が起動されないまま日が過ぎたとき」に替わります。

器は、人に起動させることはできません。決まりにできるのは二つです。起動しなかったことを記録から機械で分かるようにすることと、決めた形で閉じることです。

- 暦の期限: 検分の指摘 19 の外の期限をそのまま使います。封印から 60 暦日（日本時間）の内に本の計算を終えなければ閉じます。60 は経験の根拠の無い約束の値の案です。
- G4 の 7 日（D265）との関係: 別の期限として両方を置き、先に来た方で閉じます。段ごとの短い期限を足すこともできますが、約束の値が増えるので推しません。
- 閉じる文の案:
  - 期限で閉じたとき: 「封印から〔60〕暦日の内に本の計算を終えられなかったので、この登録を閉じた。最後に終えた段は〔段〕で、そこまでの記録はすべて公開の置き場にある。B′ の問いには答えていない。」
  - 登録者が止めると決めたとき（三つ目の案を閉じる形に限ったもの）: 最初の句を「登録者の判断で〔段〕の後に止めた（理由: 〔理由〕）ので」に替えた同じ文にします。
  - どちらでも、同じ登録の中で再び始めません。止めてから待ち、また始める道を塞ぐためです。
- 書かない語: 方向に効き目が無い・Gemma では効かない・測れなかった。
- 予想の採点:
  - q1 は、読み取りの下見の機械の決定が出ていれば採点し、出ていなければ採点しません。
  - q2〜q4 は採点しません。
  - 草案6 §4.5 の「q1 はいつも採点する（器の誤りで閉じたときは上の型）。」は、下見が走らずに閉じた場合を書いていないので、この場合を足す必要があります。

## 2. 指摘 2 について

報告の組み立ての器が組む文です。〔〕は器が転記行と札の出力から埋めます。

**k が 1 以上のとき**（四つの文をいつも全部置きます）

- 文 1: 「残った主の行〔n〕行（v̂〔n1〕・Nk〔n2〕）のうち〔k〕行（v̂〔k1〕・Nk〔k2〕・床の余白の印のある行〔m〕・印の無い行〔k−m〕）で、この読み取りの位置で、全経路を通った後の効き目は、等方のランダム方向と区別でき（Holm の後）、そのうち〔j〕行（v̂〔j1〕・Nk〔j2〕）では、実在の差の方向（兄弟を除く・両方の向き）の中でも中心からの動きが最上位だった（最上位は順位で、検定ではない）。」

- 文 3: 「この〔k〕行の効き目の側は、同じ向きで、ランダム方向より強い押しが〔s1〕行、同じ向きで、ランダム方向より弱い押しが〔s2〕行、ランダム方向と逆の向きの押しが〔s3〕行、零が等方の帰無の四分位の間にあって符号だけを書く行が〔s4〕行だった（行ごとの側と等方の帰無の中央値は主の表）。」
- 文 4: 「区別できなかった〔n−k〕行のうち〔j0〕行（v̂〔j01〕・Nk〔j02〕）では、実在の差の方向（兄弟を除く・両方の向き）の中で中心からの動きが最上位だったが、これらは等方の方向の揺れの中にあり、方向に固有の効き目は言えない（最上位は順位で、検定ではない）。」

**k が 0 のとき**（三つの文をいつも全部置きます）

- 文 1′: 「残った主の行は〔n〕行（v̂〔n1〕・Nk〔n2〕）だった。」
- 文 2′: 「どの主の行でも、この読み取りの位置で、全経路を通った後の効き目は、等方のランダム方向と区別できなかった。」
  - 草案6 §9.1〈区別できない〉の「書く」の文のままです（`design-Bprime-draft6.md` §9.1「どの主の行でも、この読み取りの位置で、全経路を通った後の効き目は、等方のランダム方向と区別できなかった」）。
- 文 3′: 「この〔n〕行のうち〔j0〕行（v̂〔j01〕・Nk〔j02〕）では、実在の差の方向（兄弟を除く・両方の向き）の中で中心からの動きが最上位だったが、これらは等方の方向の揺れの中にあり、方向に固有の効き目は言えない（最上位は順位で、検定ではない）。」

**組み方の決まり**

- 数は算用数字で埋めます。零も「0 行」と書き、文を落としません。値によって文の形が変わらないようにするためです。
- 器の assert:
  - n1＋n2＝n
  - k1＋k2＝k
  - 0 ≤ m ≤ k
  - j1＋j2＝j ≤ k
  - s1＋s2＋s3＋s4＝k
  - j01＋j02＝j0 ≤ n−k
  - 落ちたら器の誤りとして扱います。
- 〔j〕を文 1 の中に置く理由: 等方の札は低い棒で、その打ち消しに当たるのが〔j〕です。§9.1 の床の余白の印が「同じ文で置く」としたのと同じ考えで、要約の文だけを切り出しても消えないようにしました。
- 効き目の側の語は、層三の正本 `labels.side_rule` の〔〕の中の語をそのまま使います。〔〕は埋める所の印とぶつかるので、括弧は外しました。
- 同じ字の要約を、§0 と §9.1 の両方に置きます。
- 「主の表」の語は草案6 に無く、層三の報告の語を借りました（下の 3 を参照）。

**印のある行と印の無い行の並べ方**

要約では数だけを分けます。§4.3 の「要約の数は印の有る行と無い行を分けて書く」に当たるのが、文 1 の〔m〕と〔k−m〕です。

## 3. 指摘 2 の (c) について

**正本の文**（`reference/contrasts-Bl3.json`）

- `labels.p_rule_why`: 「B-lens の等方の帰無は、物差しが方向について線形なので零を中心に対称で、`(1 + #{|null| >= |m|}) / (1 + K)` を使えた。全経路の効き目は非線形で、同じ大きさの押しでも向きを問わず一方に寄りうる（帰無の中心が零からずれうる）ので、零を中心に対称な帰無を仮定しない」
- `labels.side_rule`: 「等方の外の行は、等方の帰無の中央値と、効き目の側を添えて書く。側は三つ: 中央値と同じ向きで中央値より零から遠い〔同じ向きで、ランダム方向より強い押し〕・零と中央値の間〔同じ向きで、ランダム方向より弱い押し〕・零を越えて中央値と反対の向き〔ランダム方向と逆の向きの押し〕。零が等方の帰無の下の四分位と上の四分位の間にあるときは、中央値を零とみなし、効き目の符号だけを書く（採否表 P684）」
- 関わる文として `labels.p_rule`: 「両側に等しい裾の割合: 帰無の上の裾の割合 `(1 + #{null >= m}) / (1 + K)` と下の裾の割合 `(1 + #{null <= m}) / (1 + K)` の小さい方の二倍（一を上限・K は帰無の本数・B-lens の語の側の帰無と同じ数え方・`blens_core.p_equal_tailed`）」

**正本に書いてあること**
- 全経路の効き目では、等方の帰無の中心が零からずれうる。そのため、零を中心に対称な帰無を仮定しない。
- 割合は、上と下の両方の裾で数える。
- 等方の外の行には、三つの側（強い押し・弱い押し・逆の押し）か、符号だけを添えて書く。

**正本の文を合わせた私の読み**

下の裾に出た行も〔等方の外〕になり、その行の側は「零と中央値の間〔同じ向きで、ランダム方向より弱い押し〕」でありえます。正本はこの側を、等方の外の行の側として名付けているので、そうした行が出ることを見込んでいると読めます。ただし、正本がそう明言しているわけではありません。これは定義を合わせた私の読みです。

**私が推したこと（推論）**
- Gemma で帰無の中心が実際に零からずれるか、弱い押しの行が出るかは分かりません。
- 検分では「ずれたとき、等方の中央値より弱い押しの行も「区別できた」に入ります」と書きました。正しくは「入りうる」で、推論の印も付け忘れていました。ここで直します。
- 要約だけを引いた読み手が「区別できた」を「ランダム方向より強い押し」と読むだろう、というのは読み手についての推論です。
- 反対の向きの事実も書いておきます。層三の唯一の等方の外の行は、弱い押しではなく符号だけでした。`reference/results-Bl3-FINAL-head.md` §0 の【逸脱 D-BLT1】の区画に「等方の帰無の中央値 0.03263・効き目の側: 符号だけ（零が等方の帰無の四分位の間）: 正（主の表）」とあります。層三では、中心のずれは効いていません。

**行ごとの側は、どこに添えられるか（事実）**
- 草案6 では、§5「札: 層三の正本 `labels` と同じ決まり——…・効き目の側・等方の最上位の割合・印字の決まり。」によって、`side_rule` を持ち越しています。
- §9.1 の行の文そのものには、側を入れる所がありません。草案6 の中で「効き目の側」の字が出るのは §5 と §8 だけでした（文字列で探しました）。
- 層三の報告では、側は行の文の中ではなく主の表に置かれました（同じファイル §0「（等方の帰無の中央値と効き目の側は主の表）」）。
- したがって、B′ でも側は行ごとに添えられますが、文の中か表の中かは草案6 では決まっていません。層三と同じく表になると見ます（推論）。

**要約にも要るか**

要ると考え、推します。ただし優先は、範囲の句と〔j〕より下です。
- 要約は単独で引かれやすく、〔k〕は強い押しと弱い押しを一つに数えます。
- 側を数える費用は零です（器が数えるだけ）。いつも置けば、文の形も値に依りません。
- 反対の考えもあります。側は行ごとに主の表にあるので、要約では重ねになり、文が長くなります。要約を短く保ちたいなら、最低限の代わりは次の組み合わせです。
  - §9.1 の等方の外の型の「書く」の文に、側を入れる所（床の余白の印と同じく同じ文）を足す。
  - 要約の文 3 を「（効き目の側は行ごとの文と主の表）」の添えだけにする。

**関わる事実（一つ）**

層三の凍結の本文 §9 の「読みの決まり」にある「型は重なりうる」の文は、正本の JSON の中にはありませんでした（文字列で探して 0 件）。草案6 §9.4 は `reading_rules` を持ち越すと書きますが、その JSON は型の行だけです。側の決まりは `labels.side_rule` で持ち越されますが、「型は重なりうる」は持ち越しの外になりうります（推論）。
