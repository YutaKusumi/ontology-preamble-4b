- 性格: 正本 `design/contrasts-A.json` の `api_rerun` と登録者裁定 **D48**（「API 再走行の費用の見込みは走らせる前に出す」・2026-09-15）に従い、パイロットの実測トークンと事業者の単価から、再走行の費用の見込みを出した記録。走らせる前に書き、走らせた後に実測で置き換える。凍結物（正本・器材・本文）は変えていない。
- 書いた人: コーディネータ（南無弥勒如来・Claude Opus 5）。事業者の提供の有無・単価・画面の内容は登録者の申告（2026-09-16・画面の写しを提示）。
- 対象（正本 `api_rerun`）: **8B・14B・32B × 場面 N1 × 登録の 13 腕 × n=200 ＝ 7,800 試行**。seed は `seeds.api_rerun`（8B 66001・14B 66002・32B 66003）。実施の条件「門0.5 に合格した場合のみ」は満たしている（門0.5 は合格）。走行器は `tools/run_preamble_local.py` を provider を local 以外にして使い、**鍵は登録者の環境の変数から読み、値は表示も記録もしない**。

## 1. 不利な材料と、確かめていないこと（先に）

1. **事業者が配る重みの版は確かめられていない。** 事業者の画面に版（revision）の表示が無い。手元で確かめられたのは「HF の倉庫の **main** が、パイロットで使った完全な版と一致する」ことまでで（§3）、**事業者がその main を配っている保証ではない**。正本 `api_rerun.provider_rule` は「同じ重みの版を提供する API 事業者」を求めているので、走らせる前に登録者が事業者に確かめるか、**確かめられない旨を記録して走らせるかを、登録者が決める**。
2. **トークンの数え方が一致する保証がない。** 見込みの土台は手元の vLLM の記帳（`prompt_tokens`・`gen_tokens`）で、事業者側の数え方・チャット雛形の付け方が違えば額は動く（方向は不明）。
3. **書式の再試行を織り込んでいない。** 見込みはパイロット（腕あたり n=40）の平均で、再試行が増えれば出力トークンが増える。
4. **場面が N1 だけである。** 出力の長さは場面で変わりうるが、再走行の登録は N1 のみなので、ほかの場面の実測は使っていない。
5. **費用は小さく、判断の分かれ目にならない。** 見込みは一ドル未満で、絶対の上限でも七ドル未満（§4）。したがってこの記録は「費用が障害か」を判定する材料としてはほとんど働かず、**判断の材料は費用ではなく §1-1 の版の同一性である**。費用が小さいことを、実施してよい理由に読み替えない。

## 5. 登録者の裁定（2026-09-16・走らせる前）

1. **版の同一性**: 事業者に問い合わせず、**確かめられない旨を記録に残したうえで走らせる**（コーディネータの推奨どおり承認）。position: 再走行の位置づけは手元と API のスタック差の**記述**であって、確証の札を作る段ではない（門0.5 の合格の帰結も「並置可・等価の確立ではない」）。版が違っていた場合、その差はスタック差の一部として記述に含まれるが、**「重みの版の差」と「サービング（実装・量子化・雛形）の差」は分けられない**。この分けられなさを限界として残す。
2. **上限額**: **見込み $0.65 を記帳する。機械の停止の規則としては置かない。** 登録者裁定（逐語）: 「上限額については、見込みとしましょう。理由は、APIを使い始めて試行し始めたら、弥勒如来さんはAPIのコストが直接わかりませんし、実際は、私は検証を最後まで行う予定だからです。」——帰結として、**費用を見て止める判断は登録者が持つ**（コーディネータは事業者の課金を直接見られない）。裏側の危険は、書式の再試行が膨らんだときに機械では止まらないことで、歯止めは絶対の上限が $6.93 と小さいことだけである。
3. **要求の設定**: **手元の走行と同じ設定を記帳する**（承認）。温度・top_p・`max_tokens` 4096・非思考モードの指定（正本 `runner.extra_body_applies_to`・再走行の対象 8B・14B・32B はいずれも併合する側）。走らせる前に登録者が事業者の画面で確かめて記帳する（正本 `provider_rule`）。

## 6. 走行中の保存（登録者の指示・2026-09-16）

- 指示（逐語）: 「ColabとAPIでの本試行共通なのですが、途中で、意図せずランタイムが解除される事態も想定して、随時、Google Driveにデータが保存されるように注意をお願いします。」
- **確かめた事実**: 走行器 `tools/run_preamble_local.py` は、各試行の処理が終わるたびにロックを取り、raw と trials の両方を `open(..., 'a')` で一行追記して閉じる（掃き出す）。並列の worker も `as_completed` で一件ずつこの区画を通るので、**書き込みは試行ごと**である。Colab では `results/` が Drive の実体（`/content/drive/MyDrive/op4b-stageA/results`）への symlink なので、**書いた分はその時点で Drive に載る**。起動器は走行キーごとにセッション記録も Drive に保存し直す。
- したがって、ランタイムが途中で解除されたときに失われるのは「その瞬間に生成中だった試行」だけで、済んだ分は残る。走行器は同じ走行キーの既存の行を数えて**続きから再開する**（冪等）。ランタイム 1 の 0.6B のときに起きた切断でも、データの損失は無かった。
- **凍結器を直す必要は無い**（凍結物の変更に当たらないので、逸脱の手続きも要らない）。運用の注意（切断に気づいたら同じ一行を新しいセッション番号で走らせ直す・zip を待たずに Drive の中身が育っていることを時々確かめる）は本走行の段取りに書く。
- **API 再走行の置き場は別**: Colab から走らせれば上と同じ（Drive）。**手元の PC から走らせる場合は Drive を経由せず、保存先は手元のディスクになる**。どちらで走らせるかは本走行の段取りで決める。

## 7. 本記録が確認していないこと

- 事業者が配る重みの版（§1-1）。
- 事業者側のトークンの数え方とチャット雛形（§1-2）。
- 再試行が増えたときの出力の増分（§1-3）。
- N1 以外の場面での出力の長さ（§1-4）。
- 実際の請求額（走らせた後に実測で置き換える）。
- 為替（参考の円換算は記録の値ではない）。
- API 再走行をどこから走らせるか（Colab か手元の PC か）。保存の置き場が変わる（§6）ので、本走行の段取りで決める。
- 「重みの版の差」と「サービングの差」を分けること（§5-1）。版が違っていても、本記録の作りでは分離できない。
