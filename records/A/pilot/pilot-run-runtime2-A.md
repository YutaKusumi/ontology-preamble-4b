## 1. 不利な材料（先に）

1. **最初の 8B の起動は落ちた**——`ValueError: mount failed`。新しい VM で起動器が Drive の接続を求め、同意の窓が出たところで、コーディネータが登録者に連絡してから押していただくまでの間に、Colab 側の待ち時間が切れた。Drive への書き込みは起きていない。対処は運用のみ（凍結物を変えていない）: 接続だけを行う小さなセル（`drive.mount`）を先に走らせて同意を済ませ、そのうえで同じ一行を走らせ直した。以後、新しい VM では接続を先に済ませる。
2. **0.6B の測定不能が 13 セル**（正式の門・後述 §5）。すべて 0.6B で、すべて書式外由来（ループ 0・切り詰め 0）。ほかの六機種は零。0.6B の書式外は走行の合計で 394 件（S1 152・S4 163・SK 79）。正本は「機種を本走行から外す規則は置かない」ので 0.6B は降格せず、該当セルが集計から外れる（判定は本走行）。
3. **重みの版を目で読み誤った**——8B の版をコーディネータが画面の拡大から `b968026d9c46` と読んだが、機械照合では **`b968826d9c46`**（登録の接頭辞と一致）。SHA を目視で書き写す経路は信用しない、という既往どおりの誤り。記録に載せる値はすべて器の出力（セッション記録の `model_rev_full`・DOM の文字）から取った。
4. **Drive の Web UI から落とせなかった**——Drive のタブが背景で描画されず（写しが「0 幅」で失敗）、行の座標が取れなかったので、Colab の `files.download` で落とした。常設の許可（D-35）の範囲内での経路の変更。
5. **A100 80GB が一度で割り当てられた**——登録者の経験（これまで割り当てられたことがない）と、それを受けたコーディネータの見込みの、いずれにも反する幸運な外れ。段取りが良かったからではない。次に同じ割当が得られる保証は無い（本走行の前提にしない）。
6. 逸脱を三件記帳した（D-34 撤退条件の判定に検査用の口／D-35 ダウンロードの常設許可／D-36 ランタイム操作の委任）。いずれも凍結物（正本・器材・本文）の変更ではないが、約束の分担と器の口の使い方の差である。
