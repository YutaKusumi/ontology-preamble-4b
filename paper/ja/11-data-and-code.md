# 11. 記録とスクリプトの在りか・走らせ直す手順

この論文に挙げる機種の名は、どの機種を試したかを記すためだけに使う。各社の承認や推奨ではなく、各社との関係を示すものでもない。

## 11.1 記録の在りか

記録は、公開の置き場（GitHub の `YutaKusumi/ontology-preamble-4b`）にある。段階 D の主な記録は、次のとおりである。

- 凍結した本文: `records/D1p/00-frame-D1p.md`（日本語の送る文の登録）・`records/D1pE/00-frame-D1pE.md`（英語の送る文の登録）。
- 集計の報告と、そのセルごとの数を持つ json: `records/D1p/confirm/`・`records/D1pE/confirm/`。
- 結果の報告の最終版: `records/D1p/results-D1p-FINAL-2026-10-11.md`・`records/D1pE/results-D1pE-FINAL-2026-10-13.md`。
- 閉じの記録と目録: `records/D1p/closing/`・`records/D1pE/closing/`。
- 英語の送る文の較正の記録と、訳の凍結の記録: `records/D1pE/calibration/`・`records/D1pE/translation/`。
- 前置きと場面の素材: `arms/`（英語の素材は `arms/en-D1pE/`・出典の表示は `arms/SOURCES.md`・再利用のときの事前に定めた解釈上の制約は `arms/NOTICE.md`）。
- 前の段の設計と最終版: `design/` と `records/` の段ごとの置き場、中間総括は `summary/`。
- 段階 E の記録（枠の刻印と、伏せた記録を開ける前の一覧の SHA など）: `records/E/`。

公開していない記録と、その公開の予定と、ファイルごとの SHA-256 は、付録 H にある。付録 H には、この論文が名を挙げるスクリプトと内部の記録の在りか（公開か内部か・SHA・公開の予定）の表と、実行の前に約束した SHA と公開の置き場の HEAD の SHA の照らしの表も置く。名を含む三つのファイルは公開しておらず、公開するときは名を伏せた写しになり、刻んだ SHA と合わない（節 2.6）。

## 11.2 言葉: 走らせ直しと計算の再現

この論文は、二つの手続きを分けて呼ぶ。走らせ直し（rerun）は、読み手が自分の API の鍵で、検証で使った機種のうち呼べる機種を、凍結した判定の手続き（決まり・素材・検定・判定ラベルの組み方）のまま走らせ直すことである。計算の再現は、公開の集計の報告のセルごとの数から、API を呼ばずに、すべての比べの p・区間・Holm の後の p・オッズ比・判定ラベルを組み直すことである。読み手の走らせ直しの結果と、公開の結果の比べは、同じ言語の中で、読み手の実行の中の条件の差と区間を、同じセルの公開の差と区間の隣に置く形だけで置き（率そのものは並べない）、合うか合わないかを一語で言わない。言語をまたいで並べない。走らせ直しは、公開の日に呼べる機種に限られ、使えなくなった機種（たとえば、Nscale の機種の入れ替え〔2026-10-26 から〕で下ろされる機種・在りかは節 11.4）は走らせ直せない。そのため、この論文の計算を外から確かめる主な道は、計算の再現である。計算の再現が確かめるのは、公開の数から p・区間・Holm の後の p・判定ラベルまでの計算で、数そのもの（答えの採点と分母）は確かめない。答えの文（伏せた記録）の公開の形は論文の公開の前に決め、公開されれば、凍結した採点のスクリプトで採点し直せる。条件の順の割付は種で再び作れるが、提供者の標本化は種で再び作れない（節 2.2）。

## 11.3 走らせ直しのスクリプトと、計算の再現の機能

走らせ直しのスクリプト（版 1.0）は、段階 E の枠 §7 の決まりで組む。二つの機能からなる。この版の論文の草案では、計算の再現の機能は組んで公開の数で照らし終えた。走らせ直しの機能は、版 1.0（内部の置き場の `E/tool1/op4b_rerun.py`）を組み、合成データの試し（下の「試し」の項）を通したが、本物の呼び出しによる試しはしていない。スクリプトのコードの検分は、段階 E の枠 §9 のとおり、論文の検分と別に五巡行った。版 1.0 は、四巡目までの所見を当て、五巡目で重大と中の所見が無かった版である。コードの検分では、この節の字とスクリプトの動きを照らす。

計算の再現の機能（いまは内部の置き場の `E/tool1/op4b_reproduce.py`・論文の公開のときに公開の置き場に置く）は、API を呼ばない。公開の置き場の集計の出力（日本語の送る文の登録は `records/D1p/confirm/confirm-D1p.json`、英語の送る文の登録は `records/D1pE/confirm/confirm-D1pE.json`）の、比べごとの条件の数（応答の得られた試行・破局的選択・拒否・書式外・最後の試みで出力の上限に達した試行）だけから、すべての比べの p・差の区間・オッズ比・判定の前の門・族の中の Holm の後の p・応答様式の変化の決まり・判定ラベルを、凍結した本文の決まり（付録 I）で組み直し、公開の値と照らす。線は整数の交差の積で比べ、区間の端が 0 から 1e−12 より近ければ「離れていない」とする。入力のファイルの SHA-256 は、公開の置き場の SHA の記録と照らす。起草者が 2026-10-14 に照らしたとき、日本語の送る文の登録では、設計の比べの全部（セルごとに三つの比べの 87）で、比べたすべての欄（判定の前の門・p・Holm の後の p・差と区間・オッズ比・答えなかった割合の差・破局でない答えの差と区間・判定ラベル）の組み直した値が、公開の json の値と等しかった（スクリプトが欄ごとに等しさを照らした・数の欄は浮動小数の値のまま許しの幅なしで、判定の前の門と判定ラベルは字で）。英語の送る文の登録では、設計の比べの全部（セルごとに三つの比べの 36）で、同じ欄の組み直した値が公開の json の値と等しかった。一度の起動で一つの言語だけを照らす。この照らしは起草者による照らしで、独立の照らしではなく、スクリプトのコードの検分（段階 E の枠 §9）の前である。区間と検定の型は節 2.3 のとおり（連続の補正の無い Wilson の区間と Newcombe の hybrid score・両側の Fisher の正確検定）で、スクリプトの説明にも同じ型を書く。

走らせ直しの機能は、読み手が自分の API の鍵で、検証で使った機種とセルから選んで、凍結した判定の手続き（決まり・素材・検定・判定ラベルの組み方）のまま走らせ直す機能である。段は、事前登録・在りかの確かめ・較正の選びの窓での確かめ・本番・報告の五つで、決まりは次のとおりである。

- 範囲: 二つの登録の本番の実行の設計だけ（四つの条件・凍結した場面と素材・機種ごとの標本化・凍結した採点のスクリプト・判定の前の門・Fisher の正確検定・Newcombe の区間・族の中の Holm・応答様式の変化の決まり・途中の止め）。前置きや場面を差し替える機能と、冷徹な戦略家の役の一行の条件と、破局的選択を増やす向きの操作の機能は作らない。公開の結果と比べる経路は、凍結した設定の提供者への直の経路だけで、集約の経路を持たない。これとは別に、公開の重みの機種を読み手が別の置き場で動かす機能（段階 E の枠 §7 の 4）は入れるが、印字は「読み手の申告では同じ重み・スクリプトは確かめていない」とし、公開の結果との比べの表から分ける（別の置き場へは、設定の経路の鍵を送らない）。
- 凍結の手順から外れる所: (1) 本番の前に、較正の選びの窓での確かめを足す（二つの登録の結果の後に足した・下の項）。(2) セルを一つずつ順に走らせる（凍結の設計は、経路ごとの流れを同時に起こした）。(3) DeepSeek の更新記録の照らしを入れない。(4) 時刻の決まりは当てない（凍結の時刻の決まりの目当ては費用で、判定の決まりではない・費用の見込みは混む時間の値段で数える）。(5) HTTP 401・402・403 の誤りか、四つの条件のすべてで API の誤りの割合が線を超え、条件の間の差が 3 ポイント以下の誤り（凍結した本文 §5.6 の ⑨ の決まり）を見たときは、そのセルを欠測として閉じ、401・402（鍵と残高）では同じ経路の、403 と四つの条件にそろう誤りでは同じ機種の残りのセルを走らせない（凍結の手順は、セルを閉じずに止め、補給や鍵の手当ての後に走らせ直した）。残りのセルを走らせるには、新しい作業の置き場で事前登録をし直す。(6) 二つ目のセルで採点のスクリプトの誤りが起きた後に、残りのセルを走らせないか（既定）、続けるかを、事前登録で決める（凍結の手順は、流れを止めて人が決めた・§5.6 の ②）。(7) 本番の額が額の上限（読み手の宣言か既定）に届くときは、そのセルと残りのセルの全部を走らせない（凍結の手順は、機種ごとの費用の線に届いた機種の閉じていないセルを欠測にしてほかの機種を続け、全体の上限に届いたときだけ残りの全部を欠測にした・§5.6 の ③）。凍結の実行の台本の運用の部分（刻印と走る前の push の照らし・流れの錠・集約の経路の決め）は持たない。
- 走らせる前: 読み手の事前登録のファイル（設定のファイルの SHA-256・選んだ機種とセル・条件ごとの試行の数・主の判定ラベルの組み方・費用と試行の数の上限・任意の予想）を書き出し、その SHA-256 を、書き出したときに画面に印字し、報告の頭にも刻む。セルの順は、事前登録のファイルに書いた順（設定のファイルの凍結の機種の表の順）で、較正の選びの窓での確かめの後に替えない。このとき、在りかの確かめ・較正の選びの窓での確かめ・本番の費用の上の端の見込み（節 11.5 の表と同じ数え方で、deepseek-flash は表の値段の欄のとおり混む時間の値段）と、凍結した本文 §4 の機種の表の公開の費用の見込みと、財布から出うる額の上の端（在りかの確かめと較正の選びの窓での確かめの上の端に、本番の額の上限を足した額・確かめをやり直すたびに、やり直す分の上の端の見込みが足される）と、額の上限では本番が一度も起きないセルを印字する。本番の額は、いつも額の上限で抑える（読み手が上限を付けなければ、本番の上の端の和を上限にする。新しい種の起こしや誤りの行の走らせ直しが要るセルは、上限に届けば止まるので、走らせ切るには和の 2 倍ほどの上限を事前登録で宣言する）。在りかの確かめ・較正の選びの窓での確かめ・本番は、それぞれ、読み手がその段の上の端の見込み（本番は額の上限・較正の選びの窓での確かめのやり直しは、やり直すセルの分）を引数で渡したときだけ起きる（読み手の確かめ）。在りかの確かめは、較正の選びの窓での確かめの前なら全部の機種でやり直せる。在りかの確かめでは、出力の上限 1 の呼び出しで、返った機種の名と送った文のトークンの数を照らしの元の値と比べて違いを印字し、使えない機種のセルを欠測にする。照らしの元の値（条件ごとの prompt_tokens・送る文の SHA16・返る機種の名）と値段は、言語ごとの公開の設定のファイルに置き、スクリプトは設定のファイルの SHA-256 を、スクリプトの中の値（付録 H の行と同じ値）と照らす（集約の経路の機種の名は入らない・写した値が凍結の値と同じことは内部で照らした・付録 E の逸脱 E-2）。
- 較正の選びの窓での確かめ: 本番の前に（在りかの確かめの後に）、各セルで Onull を 100 試行送り、破局的選択の率の点の値が較正の選びの窓（0.15〜0.85）の外なら「凍結のセルの選びの外」と印字する（Wilson の 95% 区間も並べる）。実行のスクリプトが止まったセル（終わりの番号の異常・止まり・整合の NG・記録の壊れた行）と、応答が試行の数の 95% に届かないセルは「判じられない」と印字し、較正の選びの窓の外のセルと同じに扱う。窓の外のセルは、読み手が名指しで続けると決めたときだけ本番を走らせ（そのようなセルがあるのに、続けるセルの名指しも止める印も無ければ、本番を起こさない）、続けたセルは報告の頭と判定ラベルに印字する。在りかの確かめと較正の選びの窓での確かめの記録は一度だけ書く。較正の選びの窓での確かめは、前の回で判じられなかったセルだけをやり直せ、セルごとに、判じられた最初の回で判じる。やり直しでは、止まりと終わりの番号の異常で判じられなかったセルは前の回の試行に続けて残りだけを走らせ、応答が足りなかったセルは誤りの行だけを一度走らせ直す（前の回の記録が壊れているか整合が合わないときだけ初めから走らせる・誤りの行を走らせ直した後も応答が足りなければ、やり直さずに判じられないままにする）。やり直したときは、回数と全部の回の値と、判じられなかった理由と判じた回を報告の頭に印字する。較正で窓の端の近くだったセルは、率が替わらなくても窓の外の印が出やすい（印は提供者の変化の証ではない）。較正と同じ試行の数（100）と、較正の選びの窓（率の点の値）で判じる。較正が見た応答の様式の崩れは、較正の選びの窓での確かめでは判じない（本番の判定の前の門が見る）。試行の数と点の値で判じることは、二つの登録の結果を見た後の 2026-10-14 に、登録者が決めた（決定 D452-2）。
